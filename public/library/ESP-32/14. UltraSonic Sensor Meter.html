02 · Concepts

What Are We Learning?

Today we are learning about Time-of-Flight and the pulseIn() function.

01 · TIME-OF-FLIGHT

Echolocation

The HC-SR04 has two silver cylinders. One is used to transmit the ultrasonic wave, while the other receives the returning echo.

We tell the ESP32 to send a tiny electrical pulse to the Trigger pin. The sensor sends an ultrasonic sound wave. The wave travels through the air, hits an object, bounces back, and reaches the Echo receiver.

If we know how long the round trip took and approximately how fast sound travels, we can calculate the distance.

02 · pulseIn()

The Microsecond Stopwatch

pulseIn() measures how long a digital pulse stays in a particular state.

For our HC-SR04, the Echo pin goes HIGH while the sound is travelling to the object and back. The function measures that HIGH duration in microseconds.

That time becomes the raw measurement that our physics math converts into centimeters.

03 · Hardware

Wiring

The HC-SR04 has four pins: VCC, TRIG, ECHO, and GND.

For this project, the sensor is powered from the ESP32's VIN / 5V supply when the board is powered from USB.

⚠️ Important ESP32 Logic-Level Warning

A standard HC-SR04 can drive its ECHO pin at about 5 V. ESP32 GPIO pins use 3.3 V logic and are not 5 V tolerant. Do not connect a standard 5 V ECHO signal directly to D18. Use a simple resistor voltage divider or a suitable 3.3 V logic-level shifter between HC-SR04 ECHO and ESP32 D18.

05 · Code

Complete Code

Delete the default code inside src/main.cpp and paste this.

Look closely at the loop(). The ESP32 first creates the ultrasonic pulse, then measures the Echo duration, performs the physics calculation, and finally updates the LEDs.

C++ 
/*
 * ============================================================
 * MY BRO'S FOURTEENTH ESP32 PROGRAM: ULTRASONIC PARKING RADAR
 * ============================================================
 */

// Define Sensor Pins
const int TRIG_PIN = 5;
const int ECHO_PIN = 18;

// Define LED Pins
const int LED_GREEN = 2;
const int LED_YELLOW = 4;
const int LED_RED = 15;

void setup() {
    Serial.begin(115200);

    // The Trigger shouts the sound (OUTPUT)
    pinMode(TRIG_PIN, OUTPUT);

    // The Echo listens for the sound (INPUT)
    pinMode(ECHO_PIN, INPUT);

    // Setup LEDs as outputs
    pinMode(LED_GREEN, OUTPUT);
    pinMode(LED_YELLOW, OUTPUT);
    pinMode(LED_RED, OUTPUT);
}

void loop() {
    // --------------------------------------------------------
    // STEP 1: SHOUT THE SOUND WAVE
    // --------------------------------------------------------

    // Clear the trigger pin first just in case
    digitalWrite(TRIG_PIN, LOW);
    delayMicroseconds(2);

    // Send a 10-microsecond pulse to trigger the sound wave
    digitalWrite(TRIG_PIN, HIGH);
    delayMicroseconds(10);
    digitalWrite(TRIG_PIN, LOW);

    // --------------------------------------------------------
    // STEP 2: MEASURE THE ECHO
    // --------------------------------------------------------

    // pulseIn() waits for the ECHO_PIN to go HIGH,
    // then measures how long it stays HIGH.
    long duration = pulseIn(ECHO_PIN, HIGH);

    // --------------------------------------------------------
    // STEP 3: THE PHYSICS MATH
    // --------------------------------------------------------

    // Speed of sound is roughly 0.034 centimeters
    // per microsecond.
    //
    // We divide by 2 because the sound traveled:
    //
    // Sensor -> Object -> Sensor
    //
    // We only want the one-way distance.
    int distanceCm = duration * 0.034 / 2;

    // Print to Serial Monitor
    Serial.print("Distance: ");
    Serial.print(distanceCm);
    Serial.println(" cm");

    // --------------------------------------------------------
    // STEP 4: VISUAL WARNING LOGIC
    // --------------------------------------------------------

    if (distanceCm > 30) {
        // FAR AWAY (Safe)
        // Only Green LED is ON.
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, LOW);
        digitalWrite(LED_RED, LOW);
    }
    else if (distanceCm > 10 && distanceCm <= 30) {
        // GETTING CLOSER (Warning)
        // Green + Yellow are ON.
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, HIGH);
        digitalWrite(LED_RED, LOW);
    }
    else {
        // TOO CLOSE (Danger)
        // All three LEDs are ON.
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, HIGH);
        digitalWrite(LED_RED, HIGH);
    }

    // Wait before pinging again so echoes do not overlap.
    delay(100);
}
⚠️ Hardware Note

The code assumes that the signal reaching ECHO_PIN is already safely reduced to ESP32 3.3 V logic through a voltage divider or level shifter.

Save your code with Ctrl + S.

06 · Deep Dive

Understand the Code

Let's break down the magic happening inside the program. ⚡

delayMicroseconds()

The Trigger Pulse

This is similar to delay(), but it works at microsecond precision.

We hold the Trigger pin HIGH for approximately 10 microseconds. That tells the HC-SR04 to start a measurement.

pulseIn()

The Stopwatch

pulseIn(ECHO_PIN, HIGH) measures how long the Echo pin remains HIGH.

The returned value is a time measurement in microseconds.

PHYSICS

The Distance Math

Sound travels at roughly 0.034 cm per microsecond under typical room-temperature conditions.

Because the measured time covers the trip to the object and back, we divide by 2.

LOGIC

Progressive Warning

The if / else if / else structure creates three distance zones.

The closer the object gets, the more LEDs turn on.

Example

Suppose the Echo duration is 100 microseconds. The calculation is approximately:

100 µs × 0.034 cm/µs = 3.4 cm round trip distance equivalent

3.4 ÷ 2 = 1.7 cm one-way distance
Why Divide by 2?

This is the key physics idea. The sensor doesn't measure only the distance from itself to the object. The echo travels: sensor → object → sensor . Therefore, the measured path is approximately twice the one-way distance.

Slow Down the Radar

Right now the radar updates roughly ten times per second because the bottom of the loop contains:

C++ 
delay(100);

What if you don't want the ESP32 constantly spamming the Serial Monitor?

EXPERIMENT

Change 100 → 2000

C++ 
delay(2000);

Now the ESP32 waits about two seconds between measurements.

This can be useful for slow-moving applications such as a simple water-level monitor or a measurement system where you don't need a constant stream of readings.

Remember

Increasing the delay also makes the warning system respond more slowly. You are trading measurement frequency for a slower update rate.

Find the final else { } block where the Red LED is turned on.

Use digitalWrite() and delay() inside that block to flash the Red LED ON and OFF quickly.

Challenge Hint

You can create a simple blink by alternating:

digitalWrite(LED_RED, HIGH);
delay(...);
digitalWrite(LED_RED, LOW);
delay(...);
What This Teaches

Because this challenge uses delay() inside the danger branch, the ESP32 will spend more time blocking while the danger state is active. That means the Serial Monitor will update more slowly during the flashing sequence.

That's okay for this beginner challenge. Later, you can rebuild the same behavior using millis() so the warning can blink without blocking the rest of the program.

11 · Debug

Troubleshooting

Serial Monitor always reads 0 cm or strange values.
Check the TRIG and ECHO wiring. Make sure TRIG is connected to D5 and ECHO reaches D18 through the required 3.3 V-safe voltage divider or level shifter. Also verify that the sensor has power and a common ground.
TRIG and ECHO were swapped.
The Trigger pin sends the command to start the ultrasonic measurement. The Echo pin reports the returning timing pulse. They are not interchangeable.
The distance jumps wildly.
Remember that the sensor uses sound. Soft surfaces, angled surfaces, very small targets, and awkward reflections can produce unstable readings. Try a flat, hard surface such as a wall or book.
The sensor gets hot or behaves strangely.
Disconnect power and re-check VCC and GND. Do not reverse the sensor's power connections. Also verify that the HC-SR04 ECHO signal is level-shifted before reaching the ESP32 GPIO.
LEDs don't behave correctly.
Check that each LED has the correct polarity, each GPIO is connected to the intended LED, and every LED has its own current-limiting resistor.
Serial Monitor shows garbage characters.
Set the Serial Monitor to 115200 baud, matching: Serial.begin(115200);
Stop If Hardware Is Getting Hot

Software bugs usually do not make you need to keep powering a physically hot component. If something is unexpectedly heating up, disconnect USB power and inspect the wiring before continuing.
