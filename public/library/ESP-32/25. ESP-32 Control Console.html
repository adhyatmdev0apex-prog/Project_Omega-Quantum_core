Hardware UI

INPUT_PULLUP Logic

Because the code uses INPUT_PULLUP , the button reads HIGH when released and LOW when pressed. The button is therefore connected directly between D14 and GND.

Check Your OLED Labels

OLED modules are not all physically arranged identically. Check the printed labels on your exact module before powering it. Some modules may place VCC/GND in a different order.

06 // SOURCE CODE

Complete Code

This is the complete control console. The most important architectural idea is the master currentMode variable and the shared refreshSystem() function.

Wi-Fi Credentials

Replace YOUR_WIFI_NAME and YOUR_PASSWORD with your actual Wi-Fi credentials. Do not commit real credentials to a public repository.

C++ 
/*
 * ============================================================
 * MY BRO'S TWENTY-FIFTH ESP32 PROGRAM: CONTROL CONSOLE
 * ============================================================
 */

#include <WiFi.h>
#include <WebServer.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

WebServer server(80);

Adafruit_SSD1306 display(128, 64, &Wire, -1);

const int BUTTON_PIN = 14;

// 1. OUR MASTER STATE VARIABLES
int currentMode = 0; // 0 = Gaming, 1 = Study, 2 = Sleep
int lastButtonState = HIGH;


// ============================================================
// HELPER FUNCTION: REFRESH THE ENTIRE SYSTEM!
// Both the Web and the Physical Button will call this function.
// ============================================================
void refreshSystem() {
    display.clearDisplay();
    display.setTextSize(2);
    display.setTextColor(WHITE);
    display.setCursor(0, 20);

    if (currentMode == 0) {
        display.println("GAMING!");
        Serial.println("Mode changed to: GAMING");
    }
    else if (currentMode == 1) {
        display.println("STUDYING!");
        Serial.println("Mode changed to: STUDY");
    }
    else if (currentMode == 2) {
        display.println("Zzz...");
        Serial.println("Mode changed to: SLEEP");
    }

    display.display(); // Push to the OLED
}


// ============================================================
// WEB ROUTES
// ============================================================
void handle_Homepage() {
    String html = "<!DOCTYPE html><html><head><meta name=\"viewport\" content=\"width=device-width, initial-scale=1\">";

    // Auto-refresh so the web dashboard tracks physical button presses!
    html += "<meta http-equiv=\"refresh\" content=\"3\">";

    html += "<style>body { font-family: sans-serif; text-align: center; margin-top: 50px; background-color: #222; color: #fff; }";
    html += "button { font-size: 20px; padding: 15px; margin: 10px; width: 80%; border-radius: 10px; border: none; font-weight: bold; }</style></head><body>";

    html += "<h1>🖥️ Console Dashboard</h1>";

    // Show the dynamic status based on the master variable
    html += "<h2>Current: <span style=\"color:orange;\">";

    if (currentMode == 0) html += "GAMING";
    else if (currentMode == 1) html += "STUDY";
    else if (currentMode == 2) html += "SLEEP";

    html += "</span></h2>";

    html += "<p>Change mode from web:</p>";

    html += "<a href=\"/set/0\"><button style=\"background: #ff3333; color: white;\">GAMING</button></a><br>";
    html += "<a href=\"/set/1\"><button style=\"background: #33cc33; color: white;\">STUDY</button></a><br>";
    html += "<a href=\"/set/2\"><button style=\"background: #3333ff; color: white;\">SLEEP</button></a><br>";

    html += "</body></html>";

    server.send(200, "text/html", html);
}


// Web direct-set routes
void handle_SetGaming() {
    currentMode = 0;
    refreshSystem();
    server.sendHeader("Location", "/");
    server.send(303);
}

void handle_SetStudy() {
    currentMode = 1;
    refreshSystem();
    server.sendHeader("Location", "/");
    server.send(303);
}

void handle_SetSleep() {
    currentMode = 2;
    refreshSystem();
    server.sendHeader("Location", "/");
    server.send(303);
}


// ============================================================
// SETUP
// ============================================================
void setup() {
    Serial.begin(115200);

    pinMode(BUTTON_PIN, INPUT_PULLUP);

    if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
        for (;;) {
            // Freeze if OLED fails
        }
    }

    display.clearDisplay();
    display.setTextSize(2);
    display.setCursor(0, 20);
    display.println("WIFI...");
    display.display();

    WiFi.begin(ssid, password);

    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
    }

    // Start with the default screen
    refreshSystem();

    server.on("/", handle_Homepage);
    server.on("/set/0", handle_SetGaming);
    server.on("/set/1", handle_SetStudy);
    server.on("/set/2", handle_SetSleep);

    server.begin();
}


// ============================================================
// LOOP
// ============================================================
void loop() {

    // 1. Listen to the web!
    server.handleClient();

    // 2. Listen to the physical button!
    int currentButtonState = digitalRead(BUTTON_PIN);

    if (lastButtonState == HIGH && currentButtonState == LOW) {

        // Button clicked! Cycle the mode forward
        currentMode = currentMode + 1;

        // Wrap around back to 0 if we go past 2
        if (currentMode > 2) {
            currentMode = 0;
        }

        // Force the screen to update with the new mode
        refreshSystem();

        delay(50); // Debounce
    }

    lastButtonState = currentButtonState;
}
Important Code Note

The HTML shown inside the C++ source is escaped because it is a C++ string. That is why you see things like &lt; and &quot; in this guide's code display. When copying the code from this page, the browser's Copy button retrieves the correct underlying text.

07 // ARCHITECTURE

Understand the Code

This is where the project becomes more than "button makes screen change." We are building a small synchronized system.

🧠

The Master Variable

currentMode is the single source of truth. It stores which mode the system is currently in.

The Three States

0 = Gaming
1 = Study
2 = Sleep

🔄

refreshSystem()

This helper function redraws the OLED according to the current state. It also prints the mode to Serial Monitor.

Why?

We avoid copying the same OLED drawing code into every button and web handler.

🔘

Physical Button

The button detects a HIGH → LOW transition, increments currentMode , wraps after 2, then calls refreshSystem() .

🌐

Web Routes

The web interface does not create another state. It directly changes the same currentMode variable.

Interface Action Shared State Result
Physical Button Increment mode currentMode OLED redraws
Web Gaming Set 0 currentMode OLED shows GAMING!
Web Study Set 1 currentMode OLED shows STUDYING!
Web Sleep Set 2 currentMode OLED shows Zzz...
Important Systems Idea

There are two interfaces, but there is only one state. That's the key to synchronization. The browser and physical button are not maintaining separate copies of the mode.

About "Multitasking"

The ESP32 is checking the web server and the physical button repeatedly inside its main loop. These tasks are interleaved rather than being literally executed simultaneously by this code.

OLED Invert Mode

Let's make Sleep mode visually different. The SSD1306 library can invert the OLED display.

🖥️

Normal Display

White pixels appear on the normal dark OLED background.

GAMING!
🌙

Sleep Display

Inverting the display produces a bright background with dark pixels.

Zzz...
Step 1 — Sleep Mode

Inside the Sleep block of refreshSystem() , place display.invertDisplay(true); after drawing the text.

C++ 
else if (currentMode == 2) {
    display.println("Zzz...");
    display.invertDisplay(true);
    Serial.println("Mode changed to: SLEEP");
}
Step 2 — Restore Normal Mode

Add display.invertDisplay(false); to the Gaming and Study blocks.

C++ 
if (currentMode == 0) {
    display.println("GAMING!");
    display.invertDisplay(false);
}

else if (currentMode == 1) {
    display.println("STUDYING!");
    display.invertDisplay(false);
}
Why This Works

The OLED keeps its inversion setting until you change it again. That is why Gaming and Study explicitly restore normal display mode.

Build a Back Button

One button moves forward through the menu. Now build another button that moves backward.

Challenge Objective

Add a second physical button

Connect a second push button to D15. Configure it with INPUT_PULLUP . When pressed, it should decrement currentMode instead of incrementing it.

➡️

Existing Button — D14

Current behavior:

currentMode = currentMode + 1;

⬅️

New Button — D15

Desired behavior:

currentMode = currentMode - 1;

The Logic Puzzle

What happens when currentMode is 0 and you subtract 1? The answer is -1. But our valid modes are only 0, 1, and 2. You therefore need to wrap the value back to 2.

C++ 
if (currentMode < 0) {
    currentMode = 2;
}
Challenge Checklist

Add D15 as an INPUT_PULLUP input → track its previous state → detect a HIGH-to-LOW press → subtract 1 → wrap negative values to 2 → call refreshSystem() .

🧠

Bonus Question

Can you make D14 and D15 act like a complete menu navigation system? D14 = next. D15 = previous. The OLED = display. The web dashboard = remote controller.

12 // DEBUG

Troubleshooting

Most problems in this project fall into three areas: state changes, OLED redraws, or web synchronization.

📺

OLED Doesn't Update

Check that the physical button block calls refreshSystem(); after changing currentMode . Changing the variable alone does not redraw the physical screen.

🌐

Phone Doesn't Update

This project uses a 3-second HTML auto-refresh. The browser is not receiving a live push notification. It reloads the page periodically.

🔘

Button Skips Modes

Mechanical buttons can bounce electrically. Keep the delay(50); debounce inside the press-detection block.

🔌

Button Always Reads Pressed

Verify that one button leg reaches D14 and the opposite leg reaches GND. Also verify that the code uses INPUT_PULLUP .

📡

Wi-Fi Doesn't Connect

Verify SSID/password, ensure the ESP32 can reach the router, and remember that this project expects a compatible 2.4 GHz network.

⚠️

OLED Connection Failed

Check VCC, GND, SDA, and SCL. The code uses I2C address 0x3C . Some OLED modules instead use 0x3D .

OLED Text Looks Wrong

If previous text remains on the screen, make sure display.clearDisplay(); happens before drawing the new mode. The Adafruit SSD1306 display uses a memory buffer, so drawing new text does not automatically erase everything that was previously there.

Debugging Strategy

When something breaks, ask three questions: Did the state change? Did refreshSystem() run? Did the interface display the new state? This separates software-state bugs from display and networking bugs.
