Up until now, every time we went wireless, we relied on a Wi-Fi router. The ESP32 connected to your home network, and your phone connected to the same network.

📡

What if there is no Wi-Fi?

Imagine a drone, RC car, robot, or weather station operating somewhere with no router and no internet connection. The devices still need a way to communicate.

⚡

Enter ESP-NOW

ESP-NOW is a lightweight wireless communication protocol from Espressif designed for direct communication between ESP32-family devices using the 2.4 GHz radio.

🤖

Real device networking

Instead of sending data through a web server, we can send compact binary data directly from one microcontroller to another.

🌐

No router required

ESP-NOW can operate without joining a conventional Wi-Fi network. The same physical radio hardware is used, but the communication model is different.

⚠️ Important correction

ESP-NOW is not a secret or proprietary invention hidden inside the ESP32. It is an Espressif wireless protocol built on the ESP32's 2.4 GHz Wi-Fi radio hardware. Also, ESP-NOW is not the same thing as Bluetooth.

🧠 What Are We Learning?

This project introduces the concepts that make device-to-device networking possible.

01
MAC ADDRESS

Hardware Identity

A MAC address identifies a network interface at the link layer. Your ESP32 has a factory-associated MAC address that can be displayed using WiFi.macAddress() .

02
BROADCAST

Talk to Everyone

The MAC address FF:FF:FF:FF:FF:FF is the broadcast destination. It tells the local radio environment that the frame is intended for all listening devices.

03
STRUCT

Binary Data Box

A C++ struct lets us group fields such as an integer and a floating-point value into one predictable binary data package.

04
CALLBACK

Event Driven Code

ESP-NOW reports send and receive events through callback functions that we register with the ESP-NOW subsystem.

⚠️ One important networking detail

A broadcast transmission does not provide a normal per-receiver acknowledgment mechanism. Therefore, a successful send callback should not be interpreted as proof that a particular other ESP32 definitely received the message. Later projects will build explicit acknowledgments when reliability matters.

1
Application data gets placed into a C++ struct.
2
ESP-NOW prepares the data for wireless transmission.
3
2.4 GHz radio sends the wireless frame.
4
Another ESP32 can receive the frame and reconstruct the struct.

📄 Complete Code

This program is a basic ESP-NOW transceiver: it initializes the radio, broadcasts a struct, and listens for incoming structs.

🚨 Compatibility note

Modern versions of the ESP32 Arduino core use callback signatures that differ from older ESP-NOW examples found online. The code below uses the modern callback form commonly used by current ESP32 Arduino cores.

C++ 
/*
 * ============================================================
 * MY BRO'S TWENTY-SIXTH ESP32 PROGRAM: ESP-NOW BROADCAST
 * ============================================================
 */

#include <esp_now.h>
#include <WiFi.h>

// ============================================================
// BROADCAST MAC ADDRESS
// FF:FF:FF:FF:FF:FF means broadcast.
// ============================================================
uint8_t broadcastAddress[] = {
    0xFF,
    0xFF,
    0xFF,
    0xFF,
    0xFF,
    0xFF
};


// ============================================================
// OUR DATA PACKAGE
// ============================================================
typedef struct struct_message {
    int boardID;
    float dummyTemp;
} struct_message;


// Create our outgoing data box.
struct_message myData;

// Information about the broadcast peer.
esp_now_peer_info_t peerInfo;


// ============================================================
// CALLBACK: DATA SENT
// ============================================================
void OnDataSent(
    const wifi_tx_info_t *txInfo,
    esp_now_send_status_t status
) {
    Serial.print("📤 Send Status: ");

    if (status == ESP_NOW_SEND_SUCCESS) {
        Serial.println("Success");
    }
    else {
        Serial.println("Fail");
    }
}


// ============================================================
// CALLBACK: DATA RECEIVED
// ============================================================
void OnDataRecv(
    const esp_now_recv_info_t *recvInfo,
    const uint8_t *incomingData,
    int len
) {
    // Make sure the incoming packet is large enough
    // to contain our complete struct.
    if (len != sizeof(struct_message)) {
        Serial.println("⚠️ Received unexpected data size.");
        return;
    }

    // Create a temporary box for the incoming data.
    struct_message receivedData;

    // Copy the raw bytes into our struct.
    memcpy(
        &receivedData,
        incomingData,
        sizeof(receivedData)
    );

    Serial.print("📥 RECEIVED MESSAGE!");
    Serial.print(" From Board ID: ");
    Serial.print(receivedData.boardID);
    Serial.print(" | Fake Temp: ");
    Serial.println(receivedData.dummyTemp);
}


// ============================================================
// SETUP
// ============================================================
void setup() {

    Serial.begin(115200);

    delay(500);

    // ESP-NOW uses the Wi-Fi radio.
    // Station mode initializes the radio appropriately.
    WiFi.mode(WIFI_STA);

    // Show this board's MAC address.
    Serial.println();
    Serial.println("🔥 ESP-NOW SYSTEM BOOTING...");

    Serial.print("My MAC Address: ");
    Serial.println(WiFi.macAddress());


    // ========================================================
    // INITIALIZE ESP-NOW
    // ========================================================
    if (esp_now_init() != ESP_OK) {
        Serial.println("❌ Error initializing ESP-NOW.");
        return;
    }


    // ========================================================
    // REGISTER CALLBACKS
    // ========================================================
    esp_now_register_send_cb(OnDataSent);
    esp_now_register_recv_cb(OnDataRecv);


    // ========================================================
    // ADD BROADCAST PEER
    // ========================================================
    memset(
        &peerInfo,
        0,
        sizeof(peerInfo)
    );

    memcpy(
        peerInfo.peer_addr,
        broadcastAddress,
        6
    );

    // 0 means use the current Wi-Fi channel.
    peerInfo.channel = 0;

    // No encryption for this beginner broadcast demo.
    peerInfo.encrypt = false;


    if (esp_now_add_peer(&peerInfo) != ESP_OK) {
        Serial.println("❌ Failed to add broadcast peer.");
        return;
    }

    Serial.println("✅ ESP-NOW READY!");
}


// ============================================================
// LOOP
// ============================================================
void loop() {

    // ========================================================
    // PACK OUR DATA
    // ========================================================
    myData.boardID = 1;
    myData.dummyTemp = 24.5;


    // ========================================================
    // BROADCAST THE DATA
    // ========================================================
    esp_err_t result = esp_now_send(
        broadcastAddress,
        (uint8_t *)&myData,
        sizeof(myData)
    );


    if (result == ESP_OK) {
        Serial.println(
            "📡 Data transmitted into the air..."
        );
    }
    else {
        Serial.println(
            "❌ Error sending the data."
        );
    }


    // Broadcast every three seconds.
    delay(3000);
}
⚠️ About the send callback

In broadcast mode, a ESP_NOW_SEND_SUCCESS result should be treated as successful transmission at the ESP-NOW/MAC level, not as proof that a specific receiver heard the packet. We will build explicit acknowledgments in a later networking project.

🧠 Understand the Code

This is where Project 26 gets seriously interesting. We are moving from web requests into binary radio communication.

🆔

MAC Address

A MAC address identifies a network interface at the link layer. The ESP32 can display its station MAC with WiFi.macAddress() .

📣

Broadcast Address

The six-byte address FF:FF:FF:FF:FF:FF represents a broadcast destination. Listening devices on the relevant radio channel can receive it.

📦

The Struct

Our struct contains two fields: int boardID and float dummyTemp . Together they form one binary payload.

⚙️

Callbacks

Instead of repeatedly checking whether a packet arrived, the ESP-NOW subsystem calls our registered callback when a receive or send event occurs.

📦 How the Struct Travels

A
Create the struct with boardID and dummyTemp .
B
Treat its memory as bytes using the uint8_t* pointer passed to esp_now_send() .
C
Radio transmission carries those bytes through the 2.4 GHz wireless system.
D
Receiver copies the bytes into another instance of the same struct.
🧩 Why does both boards need the same struct?

Because raw binary data does not contain field names such as "boardID" or "dummyTemp". Both sides need to agree on the payload layout so the received bytes are interpreted correctly.

🔁 What a Callback Means

Think of a callback like telling the ESP32: "When this event happens, run this function."

C++ 
esp_now_register_recv_cb(OnDataRecv);

We do not repeatedly call OnDataRecv() ourselves. We register it as the function to execute when ESP-NOW reports a received packet.

One Struct

Multiple values travel together as one payload.

⚡

Compact Data

Binary structs avoid the extra textual overhead of JSON for this simple microcontroller-to-microcontroller case.

🧠 Why not JSON?

JSON is excellent when humans and web applications need readable structured data. ESP-NOW applications often benefit from compact binary payloads because the communicating devices already know the data format.

🐛 Troubleshooting

ESP-NOW has a few networking-specific failure points. Let's eliminate them systematically.

❌

ESP-NOW Init Fails

Make sure WiFi.mode(WIFI_STA) runs before esp_now_init() . Also check that your ESP32 board package supports ESP-NOW.

📡

Two boards don't communicate

Check that both boards are operating on a compatible Wi-Fi channel and that both have ESP-NOW initialized successfully.

🆔

MAC address confusion

Use WiFi.macAddress() to print the station MAC of each board. Make sure you are recording the address from the correct device.

📦

Garbage data

Both sides must agree on the struct layout. Check sizeof(struct_message) and make sure the receiver validates the incoming packet length.

⚠️ Don't assume "Delivery Fail" means the radio is broken

Broadcast behavior is different from point-to-point communication. A send callback reports transmission status, but broadcast does not give you a normal receiver-specific acknowledgment. Later, when we use direct peers, we can design explicit application-level acknowledgments.

Problem Check
ESP-NOW won't initialize Station mode, board package, initialization result
No incoming packet Second board powered, same compatible channel, ESP-NOW ready
Wrong values received Struct layout, payload size, matching firmware
Callback compilation error Check whether your ESP32 Arduino core expects the modern callback signatures used in this guide
Serial output is garbage Set Serial Monitor to 115200 baud
🛠️ Debugging strategy

Don't change ten things at once. First prove that each board boots. Then prove ESP-NOW initializes. Then print MAC addresses. Then prove sending. Then prove receiving. Then add more complicated payloads.

🧠 New Vocabulary

These four words are worth remembering. They will appear again and again in embedded networking.

Word Meaning
ESP-NOW An Espressif wireless protocol for lightweight communication between supported ESP devices using the 2.4 GHz radio.
MAC Address A link-layer hardware address used to identify a network interface.
Struct A custom C++ data type that groups multiple fields into one object.
Callback A function registered to be called when a particular event occurs.
Peer A device configured as a communication partner for ESP-NOW operations.
Broadcast A transmission addressed to all listening devices on the relevant local wireless medium.
