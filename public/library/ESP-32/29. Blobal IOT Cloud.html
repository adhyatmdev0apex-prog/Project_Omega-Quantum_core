03 / CLOUD

Set Up ThingSpeak

Before touching the C++ code, create the cloud destination that will receive your sensor data.

  1. Open ThingSpeak in your computer's browser and create or sign into your account.
  2. Create a new channel.
  3. Give your channel a name such as: My ESP32 Weather Station.
  4. Enable Field 1, Field 2, and Field 3.
  5. Name Field 1: Temperature (C)
  6. Name Field 2: Humidity (%)
  7. Name Field 3: Light Level
  8. Save the channel.
  9. Open the channel's API Keys section.
  10. Find the Write API Key and copy it somewhere safe. You will put it into the C++ program.
⏱️ THE 15-SECOND RULE

ThingSpeak's standard free-channel update interval is commonly limited to about 15 seconds. Our program therefore waits 15 seconds between uploads. Sending faster than the service permits can cause updates to be rejected or throttled. Don't treat the cloud like a firehose — respect its rate limit.

04 / HARDWARE

Wire the Sensors

This is the same sensor architecture you've already used. The DHT11 provides digital temperature/humidity data, while the LDR and 10kΩ resistor form an analog voltage divider.

🌡️ DHT11

  • VCC (+) → 3V3
  • DATA (S) → D4
  • GND (-) → Blue GND rail

☀️ LDR Divider

  • LDR leg 1 → 3V3
  • LDR leg 2 → shared breadboard row
  • 10kΩ resistor → same shared row
  • Other resistor leg → GND
  • Shared row → D34
Wiring Map

D4  ────────────────────────► DHT11 DATA
GND ────────────────────────► DHT11 GND

                               │
                               ▼

                               │

GND ────────────────────────► BLUE GND RAIL


ESP32 GND ──────────────────► BLUE GND RAIL
🧠 WHY THE LDR NEEDS TWO COMPONENTS

The ESP32 does not directly measure resistance. The LDR and 10kΩ resistor form a voltage divider, converting the changing resistance of the LDR into a voltage that the ESP32 can measure with analogRead().

06 / CODE

Complete Code

This is the entire cloud uploader. Replace the Wi-Fi placeholders and ThingSpeak API key before uploading.

🚨 CRITICAL — ADD YOUR CREDENTIALS

Replace YOUR_WIFI_NAME, YOUR_PASSWORD, and YOUR_THINGSPEAK_WRITE_API_KEY. Never publish the real API key in public code.

C++ 
/*
 * ============================================================
 * MY BRO'S TWENTY-NINTH ESP32 PROGRAM: GLOBAL IOT CLOUD
 * ============================================================
 */

#include <WiFi.h>
#include <HTTPClient.h>
#include "DHT.h"

// 1. YOUR NETWORK DETAILS
const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

// 2. YOUR THINGSPEAK DETAILS
// Replace this with the Write API Key from your channel.
String apiKey = "YOUR_THINGSPEAK_WRITE_API_KEY";

// 3. SENSOR SETUP
const int DHT_PIN = 4;
#define DHT_TYPE DHT11
DHT dht(DHT_PIN, DHT_TYPE);

const int LDR_PIN = 34;

// 4. TIMER VARIABLES
// ThingSpeak updates should not be sent faster than
// the service's allowed update interval.
unsigned long previousMillis = 0;
const long interval = 15000;

void setup() {
    Serial.begin(115200);

    dht.begin();

    Serial.print("Connecting to Wi-Fi");

    WiFi.begin(ssid, password);

    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }

    Serial.println("\n🔥 Wi-Fi Connected!");
}

void loop() {
    unsigned long currentMillis = millis();

    // Check if 15 seconds have passed.
    if (currentMillis - previousMillis >= interval) {
        previousMillis = currentMillis;

        // ----------------------------------------------------
        // 1. READ SENSORS
        // ----------------------------------------------------

        float temp = dht.readTemperature();
        float hum = dht.readHumidity();
        int light = analogRead(LDR_PIN);

        // Make sure the DHT11 actually worked.
        if (isnan(temp) || isnan(hum)) {
            Serial.println(
                "DHT11 read failed, skipping this upload."
            );

            return;
        }

        Serial.println("\n--- New Reading ---");

        Serial.print("Temp: ");
        Serial.print(temp);
        Serial.println(" C");

        Serial.print("Humidity: ");
        Serial.print(hum);
        Serial.println(" %");

        Serial.print("Light: ");
        Serial.println(light);

        // ----------------------------------------------------
        // 2. PREPARE THE DATA UPLOAD
        // ----------------------------------------------------

        if (WiFi.status() == WL_CONNECTED) {
            HTTPClient http;

            // Build the ThingSpeak URL.
            String url =
                "http://api.thingspeak.com/update?api_key=" +
                apiKey +
                "&field1=" + String(temp) +
                "&field2=" + String(hum) +
                "&field3=" + String(light);

            Serial.println(
                "☁️ Pushing data to ThingSpeak Cloud..."
            );

            // Open the HTTP connection.
            http.begin(url);

            // Send the GET request.
            int httpCode = http.GET();

            // Check the result.
            if (httpCode > 0) {
                Serial.print(
                    "✅ Cloud Upload Success! "
                    "Server Response Code: "
                );

                Serial.println(httpCode);
            }
            else {
                Serial.println(
                    "❌ Cloud Upload FAILED!"
                );
            }

            // Close the HTTP connection.
            http.end();
        }
        else {
            Serial.println(
                "Wi-Fi Disconnected!"
            );
        }
    }
}
🧩 THE WHOLE PIPELINE

Sensor values become C++ variables → the variables become URL parameters → HTTP sends the request → ThingSpeak receives it → the channel stores it → the dashboard graphs it.

07 / DECODE

Understand the Code

This project introduces a major architectural change: your ESP32 is no longer only a server. It is now an Internet client sending telemetry to another computer system.

🌐 HTTPClient

HTTPClient lets the ESP32 make HTTP requests to another server. In Project 28, you used it to download weather data. Here, you use it to upload your own data.

☁️ ThingSpeak URL

The URL contains the API key and sensor values as query parameters. ThingSpeak reads those parameters and associates them with the correct channel.

📊 Telemetry

Telemetry means measurements collected from a remote device and transmitted elsewhere. Temperature, humidity, and light are our telemetry data.

⏱️ millis()

Instead of using a long delay(15000), the program checks elapsed time with millis(). This gives the rest of the program a chance to continue running between uploads.

10 / EXPERIMENT

Break the Rate Limit

Now let's deliberately make a bad engineering decision and observe why server-side rate limits exist.

🧪 Change This

C++ 
const long interval = 15000;

Change it temporarily to:

C++ 
const long interval = 2000;
⚠️ DON'T LEAVE IT LIKE THIS

A 2-second update interval is faster than the normal free ThingSpeak channel update allowance. You may see rejected, throttled, or otherwise unsuccessful updates. Exact behavior depends on the service and account limits; the important engineering lesson is that cloud services impose rate limits.

🔧 Restore It

Put the value back to:

C++ 
const long interval = 15000;
Engineering lesson: More requests does not automatically mean a better system. Good distributed systems respect the capacity and rules of the services they communicate with.
11 / CHALLENGE

Cloud Upload Indicator

Let's give the ESP32 physical feedback whenever a cloud upload succeeds.

OBJECTIVE // HARDWARE FEEDBACK

Make an LED blink after a successful upload.

Add a green LED to GPIO D2. Whenever the ESP32 receives a successful HTTP response, flash the LED for a tiny moment.

🚨 LED SAFETY

Do not connect an LED directly between a GPIO and GND without current limiting. Use a 220–330Ω resistor in series with the LED. Example: D2 → resistor → LED long leg → LED short leg → GND.

Challenge Wiring 
ESP32 D2 ─────► 220–330Ω RESISTOR ─────► LED LONG LEG (+)

ESP32 GND ─────────────────────────────► LED SHORT LEG (-)

Step 1 — Configure the LED

Add this to setup():

C++ 
pinMode(2, OUTPUT);
digitalWrite(2, LOW);

Step 2 — Flash on Success

Find the successful HTTP response block:

C++ 
if (httpCode > 0) {
    Serial.print(
        "✅ Cloud Upload Success! "
        "Server Response Code: "
    );

    Serial.println(httpCode);

    digitalWrite(2, HIGH);
    delay(200);
    digitalWrite(2, LOW);
}
🧠 THINK LIKE AN ENGINEER

Right now, delay(200) is acceptable for this beginner feedback indicator because the blink only happens after an upload. Later, when your system has more simultaneous jobs, you can replace blocking delays with non-blocking timing using millis().

⚠️ GPIO2 NOTE

GPIO2 is commonly associated with the onboard LED and bootstrapping behavior on some ESP32 boards. For this beginner experiment, using it as shown is reasonable, but avoid designing external boot-critical circuitry around GPIO2 without understanding the board's boot behavior.

12 / DEBUG

Troubleshooting

Cloud projects introduce a few new failure points: sensor → ESP32 → Wi-Fi → Internet → HTTP → cloud service.

❌ DHT11 Read Failed

Check VCC, DATA, and GND. Make sure DATA is actually connected to D4. A loose sensor connection can produce invalid readings, which isnan() detects.

❌ Upload Failed

Check the Serial Monitor. Verify that the ESP32 is still connected to Wi-Fi and that the ThingSpeak API key is correct.

❌ No Cloud Data

Check that you enabled Field 1, Field 2, and Field 3 in the channel. Also verify that your program's field numbers match the channel configuration.

❌ Updates Too Fast

Restore the interval to 15000. Cloud platforms impose update limits to protect their infrastructure.

❌ Wi-Fi Never Connects

Check your SSID and password carefully. Remember that the ESP32 DevKit V1 uses 2.4 GHz Wi-Fi, not 5 GHz-only networks.

❌ Light Value Looks Strange

Inspect the LDR voltage-divider wiring. The shared LDR/resistor node must connect to D34.

🔐 API KEY CHECK

If the API key is wrong, do not paste your real key into a public support forum or screenshot. Verify it privately in your ThingSpeak channel settings.

Symptom First Thing to Check
Wi-Fi dots forever SSID, password, 2.4 GHz network
DHT11 NaN DHT11 wiring and sensor power
No ThingSpeak graph data API key, channel fields, Internet access
Updates rejected 15-second update interval
Light always 0 or 4095 LDR voltage-divider wiring
