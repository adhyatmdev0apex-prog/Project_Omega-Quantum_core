🧠 3. WHAT IS AN INPUT?

So far, you've used GPIOs as outputs. With an output, the ESP32 says: “I want to control this pin.”

Now we want the opposite. We want the ESP32 to ask: “Is the button being pressed?”

OUTPUT ESP32 │ ▼ GPIO │ ▼ LED INPUT BUTTON │ ▼ GPIO │ ▼ ESP32
This is one of the most fundamental concepts in electronics.

🔘 4. WHAT DOES A BUTTON ACTUALLY DO?

A push button is basically a switch.

NOT PRESSED ──── ──── connection open PRESSED ──────────── connection closed

The ESP32 can detect this change.

🧠 5. OUR BUTTON CIRCUIT — INPUT_PULLUP

We're going to use the ESP32's INPUT_PULLUP. The internal pull-up resistor gives the GPIO a stable default state.

ESP32 D4 │ ▼ ┌─────────┐ │ BUTTON │ └────┬────┘ │ ▼ GND
⚠️ This can feel backwards at first.
Pressed = LOW
Released = HIGH

💻 12. THE COMPLETE PROGRAM

Paste this entire program:

/*
 * ============================================================
 * MY BRO'S ESP32 — LED + BUTTON
 * ============================================================
 *
 * This program teaches the ESP32 how to:
 *
 *     1. CONTROL an LED
 *     2. READ a physical button
 *
 * Hardware:
 *
 *     LED    → D2 / GPIO 2
 *     BUTTON → D4 / GPIO 4
 *
 * The behavior:
 *
 *     Button NOT pressed → LED OFF
 *     Button PRESSED     → LED ON
 *
 * Button wiring:
 *
 *     D4 → BUTTON → GND
 *
 * We use INPUT_PULLUP, which activates the ESP32's
 * internal pull-up resistor.
 *
 * Therefore:
 *
 *     Button released → GPIO reads HIGH
 *     Button pressed   → GPIO reads LOW
 *
 * ============================================================
 */

const int LED_PIN = 2;
const int BUTTON_PIN = 4;

void setup()
{
    pinMode(LED_PIN, OUTPUT);
    pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop()
{
    int buttonState = digitalRead(BUTTON_PIN);

    if (buttonState == LOW)
    {
        digitalWrite(LED_PIN, HIGH);
    }
    else
    {
        digitalWrite(LED_PIN, LOW);
    }
}

Save with Ctrl + S.

🧠 13. LET'S UNDERSTAND THE NEW CODE

This project introduces three major new ideas:

  • digitalRead()
  • if / else
  • INPUT_PULLUP

These are extremely important for interactive embedded systems.

🔵 14. digitalRead()

Previously you learned digitalWrite(), which means WRITE something to a GPIO.

digitalRead() means READ the state of a GPIO.

int buttonState = digitalRead(BUTTON_PIN);

The ESP32 asks: “What is currently happening on GPIO 4?” The result will be HIGH or LOW.

🧠 15. digitalWrite() VS digitalRead()

FunctionPurposeDirection
digitalWrite()Control a GPIOProgram → Output
digitalRead()Read a GPIOInput → Program
digitalWrite(LED_PIN, HIGH);

Means: set the LED GPIO HIGH.

digitalRead(BUTTON_PIN);

Means: tell me whether the button GPIO is HIGH or LOW.

🔘 16. UNDERSTANDING INPUT_PULLUP

pinMode(BUTTON_PIN, INPUT_PULLUP);

Normally, pinMode(BUTTON_PIN, INPUT) configures a pin as an input. INPUT_PULLUP also enables the ESP32's internal pull-up.

This gives the GPIO a stable default state.

⚡ 17. WHY DO WE NEED A PULL-UP?

Without a defined pull-up or pull-down, an input can float. A floating input may randomly appear HIGH or LOW.

ESP32 │ internal pull-up │ ▼ D4 │ BUTTON │ ▼ GND

When released: D4 → HIGH.

When pressed: D4 → LOW.

🔄 18. WHY IS PRESSED = LOW?

BUTTON PRESSED ↓ D4 connected to GND ↓ 0V ↓ LOW

Because the button connects D4 to GND when pressed. GND is the 0 V reference, so the input reads LOW.

🧠 19. WHAT IS if?

if (buttonState == LOW)
{
    digitalWrite(LED_PIN, HIGH);
}

In simple English:

IF the button state is LOW, turn the LED ON.

Programming lets the ESP32 make decisions based on input.

🔀 20. WHAT IS else?

else
{
    digitalWrite(LED_PIN, LOW);
}

That means: if the if condition wasn't true, do this instead.

IF button is pressed ↓ LED ON OTHERWISE ↓ LED OFF

🧩 21. UNDERSTANDING ==

== means compare. It asks:

Is buttonState equal to LOW?

This is different from a single =, which is used for assignment.

int buttonState = digitalRead(BUTTON_PIN);

Assignment: put the result into buttonState.

buttonState == LOW

Comparison: check whether the value equals LOW.

🔁 22. HOW THE WHOLE PROGRAM WORKS

READ BUTTON ↓ ┌──────────┐ │ PRESSED? │ └────┬─────┘ YES│NO ┌───┴───┐ ↓ ↓ LED ON LED OFF │ │ └───┬───┘ ↓ READ AGAIN ↓ ...
  1. Read the button.
  2. Check its state.
  3. If pressed, turn LED ON.
  4. If not pressed, turn LED OFF.
  5. Start over because loop() repeats forever.

⚠️ 31. delay() AND BUTTONS

Suppose you write:

delay(5000);

The ESP32 spends 5 seconds waiting. During that time, this simple program isn't continuously checking the button.

Later we'll learn better timing methods such as:

millis()
⚠️ delay() is easy, but it blocks the normal flow of your program.

🚨 37. IF THE LED DOESN'T WORK

  1. Check the LED direction and try reversing it.
  2. Make sure the LED is connected to D2.
  3. Make sure the other side reaches GND.
  4. Make sure PlatformIO successfully uploaded the new program.

🚨 38. IF THE BUTTON DOESN'T WORK

  1. Check D4 → BUTTON.
  2. Check BUTTON → GND.
  3. Use pinMode(BUTTON_PIN, INPUT_PULLUP);.
  4. Check the breadboard button orientation. Try rotating it 90° if pressing it doesn't change anything.

🚨 39. IF THE BUTTON ALWAYS SEEMS PRESSED

If the LED stays ON constantly, check whether D4 is accidentally connected directly to GND without the button acting as the switch.

BUTTON PRESSED → D4 = LOW
BUTTON RELEASED → D4 = HIGH

🚨 40. IF THE BUTTON BEHAVES RANDOMLY

Check that you are actually using:

INPUT_PULLUP

The internal pull-up gives the input a defined default state. Without a suitable pull-up or pull-down arrangement, a digital input can float and produce unreliable readings.
