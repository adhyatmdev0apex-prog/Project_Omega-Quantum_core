02
Core Concepts

WHAT ARE WE LEARNING?

Today we are learning about State Variables and Debouncing.

01 // State Variable

The ESP32 processes code thousands of times per second.

By default, it has the memory of a goldfish. 🐟

If we want it to act like a real light switch, we need to give it a "memory box" — a variable — to remember two things:

  • Is the LED currently ON or OFF?
  • Was the button being pressed a microsecond ago?
02 // State Change — The Edge

Instead of asking:

"Is the button pressed right now?"

We are going to teach the ESP32 to ask:

"Did the button just change from unpressed to pressed?"

We only want to flip the light switch exactly at the moment your finger clicks the button down.

03 // Debouncing

Real buttons are made of springy metal.

When you press one, the metal contacts bounce against each other microscopically.

The ESP32 is so fast that it might read one physical click as 10 fast clicks, causing the LED to flicker randomly.

We will use a tiny delay() to ignore the metal bouncing.

Source Code

COMPLETE CODE

Delete the default code and paste this in. Read the comments — this is where the real logic happens!

C++ // main.cpp 
/*
 * ============================================================
 * MY BRO'S FIFTH ESP32 PROGRAM: BUTTON TOGGLE
 * ============================================================
 */

const int LED_PIN = 2;
const int BUTTON_PIN = 14;

// 1. CREATE OUR MEMORY BOXES (VARIABLES)
// We put these at the very top so the ESP32 remembers them forever.

// This remembers if the LED is currently supposed to be ON (HIGH) or OFF (LOW)
int ledState = LOW;

// This remembers what the button was doing the last time we checked
int lastButtonState = HIGH;

void setup() {
    pinMode(LED_PIN, OUTPUT);
    pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop() {

    // Read what the button is doing RIGHT NOW
    int currentButtonState =
        digitalRead(BUTTON_PIN);

    // 2. CHECK FOR A STATE CHANGE (The Click!)
    // Was it unpressed (HIGH) a moment ago?
    // AND is it pressed (LOW) right now?

    if (
        lastButtonState == HIGH
        &&
        currentButtonState == LOW
    ) {

        // The button was JUST clicked!
        // Time to flip the LED state.

        if (ledState == LOW) {
            ledState = HIGH;
        }
        else {
            ledState = LOW;
        }

        // Command the LED to match our new memory
        digitalWrite(LED_PIN, ledState);

        // 3. DEBOUNCE
        // Wait 50 milliseconds so the metal springs
        // inside the button settle down.

        delay(50);
    }

    // 4. UPDATE OUR MEMORY FOR THE NEXT LOOP
    // Save the current button state into the "last" box.

    lastButtonState = currentButtonState;
}

06
Software Logic

UNDERSTAND THE CODE

This is your first step into actual software-engineering logic! 🧠

&& — AND Operator

Inside our if statement we wrote:

lastButtonState == HIGH && currentButtonState == LOW

The && means AND.

The code will only run if BOTH sides are true.

The Flip

When a click is detected, we look inside the ledState box.

If it says LOW, we replace it with HIGH.

If it says HIGH, we replace it with LOW.

That's our toggle.

The Memory Snapshot

This line is crucial:

lastButtonState = currentButtonState;

At the end of the loop, the ESP32 takes a mental snapshot of the button.

"Okay, my finger is holding the button down."

That way, on the next loop, it knows you are holding the button, not clicking it a second time.

11
Diagnostics

TROUBLESHOOTING

⚠
The LED only stays on while holding the button
Double-check your if statement. Did you write == (compare) or = (assign)? It must be lastButtonState == HIGH.
⚠
The button is acting weird and glitchy
Make sure you didn't accidentally delete the delay(50) debounce code, and make sure your button is firmly seated in the breadboard.
⚠
LED doesn't change at all
Did you remember to put lastButtonState = currentButtonState; at the very bottom of your loop? If you forgot this, the ESP32's memory never updates.

Vocabulary

NEW VOCABULARY

Word Meaning
State The current condition of a system, such as whether the light is ON or OFF right now.
Toggle To switch back and forth between two states, like a light switch.
Debounce Using a tiny delay in code to ignore the physical bouncing or glitching of metal button contacts.
&& AND Operator Used to combine two conditions. Both must be true for the code to run.
