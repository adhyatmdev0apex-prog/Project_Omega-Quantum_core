03 // Data Partitioning

What Are We Learning?

Today we're learning how one large data range can be divided into smaller regions.

Data Partitioning

Our potentiometer gives us a large range: 0 to 4095 .

We want to divide that journey into three sections, one for each LED.

constrain()

When map() receives a value outside its input range, its output can go outside the desired 0–255 PWM range.

constrain() traps that result inside a safe numerical boundary.

0 → 1365 LED 1 fades
OFF → FULL
1366 → 2730 LED 1 FULL
LED 2 fades
2731 → 4095 LEDs 1 + 2 FULL
LED 3 fades
The Core Idea

Instead of treating 0–4095 as one giant range, we're creating three smaller mathematical zones and assigning each zone a different output behavior.

06 // Core Firmware

Complete Code

Delete the default code and paste this in. Look closely at how map() and constrain() work together.

C++ 
/*
 * ============================================================
 * MY BRO'S ELEVENTH ESP32 PROGRAM: 3-LED VOLUME METER
 * ============================================================
 */
#include "Arduino.h"

const int POT_PIN = 34;

const int LED_1 = 25;
const int LED_2 = 26;
const int LED_3 = 27;

void setup() {
    Serial.begin(115200);

    // Set all three LEDs as outputs.
    pinMode(LED_1, OUTPUT);
    pinMode(LED_2, OUTPUT);
    pinMode(LED_3, OUTPUT);
}

void loop() {
    // --------------------------------------------------------
    // 1. READ THE RAW KNOB VALUE
    // --------------------------------------------------------
    // Read the potentiometer.
    // The ESP32 ADC reading is approximately 0 to 4095.
    int potValue = analogRead(POT_PIN);

    // --------------------------------------------------------
    // 2. CALCULATE LED 1
    // --------------------------------------------------------
    // Bottom third of the knob range.
    int pwm1 = map(
        potValue,
        0,
        1365,
        0,
        255
    );

    // Keep the PWM value strictly inside 0 to 255.
    pwm1 = constrain(
        pwm1,
        0,
        255
    );

    // --------------------------------------------------------
    // 3. CALCULATE LED 2
    // --------------------------------------------------------
    // Middle third of the knob range.
    int pwm2 = map(
        potValue,
        1365,
        2730,
        0,
        255
    );

    pwm2 = constrain(
        pwm2,
        0,
        255
    );

    // --------------------------------------------------------
    // 4. CALCULATE LED 3
    // --------------------------------------------------------
    // Top third of the knob range.
    int pwm3 = map(
        potValue,
        2730,
        4095,
        0,
        255
    );

    pwm3 = constrain(
        pwm3,
        0,
        255
    );

    // --------------------------------------------------------
    // 5. SEND THE POWER TO THE LEDs
    // --------------------------------------------------------
    analogWrite(
        LED_1,
        pwm1
    );

    analogWrite(
        LED_2,
        pwm2
    );

    analogWrite(
        LED_3,
        pwm3
    );

    // --------------------------------------------------------
    // 6. LOG THE VALUES TO THE SERIAL MONITOR
    // --------------------------------------------------------
    Serial.print("Knob: ");
    Serial.print(potValue);

    Serial.print(" | L1: ");
    Serial.print(pwm1);

    Serial.print(" | L2: ");
    Serial.print(pwm2);

    Serial.print(" | L3: ");
    Serial.println(pwm3);

    // Fast loop for smooth fading.
    delay(20);
}
Save

Save your code with Ctrl + S before building.

07 // Code Breakdown

Understand the Code

This is where the engineering math becomes visible.

LED 2's Mapping

Look at:

C++ 
int pwm2 = map(
    potValue,
    1365,
    2730,
    0,
    255
);

Imagine the knob is halfway turned, so potValue = 2000 .

For LED 2, 2000 sits inside its 1365–2730 input range. Therefore, map() calculates a PWM value around the middle of the 0–255 output range.

What Happens Outside the Range?

If potValue = 0 , that value is below LED 2's mapping range. The raw map() result can therefore become negative.

That's exactly why we use constrain() .

constrain()

This line:

pwm2 = constrain(pwm2, 0, 255);

tells the program: "This value must stay between 0 and 255."

A negative result becomes 0. A result above 255 becomes 255.

1 // READ

Potentiometer produces a raw value between approximately 0 and 4095.

↓
2 // PARTITION

The input is interpreted across three separate ranges.

↓
3 // MAP

Each range is converted into a 0–255 PWM value.

↓
4 // CONSTRAIN

Values outside 0–255 are trapped inside the allowed output range.

↓
5 // OUTPUT

The three PWM values control the three LEDs.

10 // Experiment

Make the Bar Snap

Let's change the feel of the physical controller.

The Experiment

What if we want a sudden "snapping" bar instead of a smooth fade?

We can make an LED's fade happen across a tiny section of the potentiometer's range.

C++ 
int pwm2 = map(
    potValue,
    2000,
    2100,
    0,
    255
);

Save and upload.

Now LED 2 remains off for most of the potentiometer's journey, then changes very quickly once the knob enters the 2000–2100 region.

Engineering Insight

The mathematics behind the control determines how the physical control feels.

A wide mapping range creates a smooth, gradual response. A tiny mapping range creates a sharp, sensitive response.

11 // Engineering Challenge

Reverse the Bar

Can you make the meter fill from Right to Left?

Objective

Make the bar fill in the opposite physical direction.

When the knob is at 0 , everything should still be OFF.

As the knob increases:

  • LED 3 fades on first.
  • Then LED 2.
  • Then LED 1.
Hint

You don't need to change any wires.

You don't need to change the math numbers.

Just swap the variable names in the analogWrite() commands at the bottom.

Think Before You Edit

The calculations don't care which physical LED receives the result.

The final output commands determine which LED gets each calculated PWM value.

12 // Debugging

Troubleshooting

Debug the signal path one stage at a time.

LEDs Flicker Crazily

Check whether you accidentally deleted the constrain() lines.

Each PWM result should be kept inside the intended 0–255 range.

Bar Fills Backwards

Check the potentiometer's outer-leg connections.

Swapping the 3V3 and GND outer connections reverses the direction of the measured voltage.

One LED Doesn't Work

Check that the LED is plugged into the correct breadboard row.

Verify the corresponding pinMode(..., OUTPUT) exists in setup() .

Potentiometer Does Nothing

Verify that the middle leg is connected to D34 .

Verify the outer legs connect to 3V3 and GND .

Debug Pipeline

Check: Potentiometer → D34 → analogRead() → map() → constrain() → analogWrite() → LEDs

13 // Vocabulary

New Vocabulary

Two concepts from this project are especially important.

Word Meaning
constrain(value, min, max) A function that traps a number inside a specified boundary. It prevents a calculated value from spilling below the minimum or above the maximum.
Data Partitioning Taking a large piece of data, such as a 0–4095 range, and splitting it into smaller, manageable chunks for different tasks.
PWM Pulse Width Modulation. A technique used here to control the apparent brightness of LEDs.
Mapping Converting a value from one numerical range into another numerical range.
