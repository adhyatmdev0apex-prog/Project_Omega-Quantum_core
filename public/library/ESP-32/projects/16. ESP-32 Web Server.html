03 / Wiring

Connect the Radar

The HC-SR04 has four connections: VCC, TRIG, ECHO, and GND. We're using three LEDs to show the distance zone.

Sensor Connections

HC-SR04

VCC

Connect the HC-SR04 VCC pin to VIN / 5V on the ESP32.

TRIG

Connect TRIG to D5 / GPIO 5. The ESP32 uses this output to start a measurement.

ECHO

Connect ECHO to D18 / GPIO 18 through a voltage divider.

GND

Connect GND to the breadboard's blue ground rail and connect that rail to an ESP32 GND pin.

⚠️ IMPORTANT — ECHO VOLTAGE: A typical HC-SR04 powered from 5 V can produce a roughly 5 V Echo signal. ESP32 GPIO pins are 3.3 V logic and should not receive 5 V directly. Use a simple resistor voltage divider between ECHO and D18. For example, use 1 kΩ from HC-SR04 ECHO to D18 and 2 kΩ from D18 to GND. This keeps the ESP32 input around 3.3 V.

05 / Complete Code

The Parking Radar

Delete the default code in src/main.cpp and paste this. Look closely at the trigger pulse, Echo measurement, and distance calculation.

C++ 
/*
 * ============================================================
 * MY BRO'S FOURTEENTH ESP32 PROGRAM: ULTRASONIC PARKING RADAR
 * ============================================================
 */

// Define Sensor Pins
const int TRIG_PIN = 5;
const int ECHO_PIN = 18;

// Define LED Pins
const int LED_GREEN = 2;
const int LED_YELLOW = 4;
const int LED_RED = 15;

void setup() {
    Serial.begin(115200);

    // The Trigger shouts the sound (OUTPUT)
    pinMode(TRIG_PIN, OUTPUT);

    // The Echo listens for the sound (INPUT)
    pinMode(ECHO_PIN, INPUT);

    // Setup LEDs as outputs
    pinMode(LED_GREEN, OUTPUT);
    pinMode(LED_YELLOW, OUTPUT);
    pinMode(LED_RED, OUTPUT);
}

void loop() {
    // --------------------------------------------------------
    // STEP 1: SHOUT THE SOUND WAVE
    // --------------------------------------------------------
    // Clear the trigger pin first just in case
    digitalWrite(TRIG_PIN, LOW);
    delayMicroseconds(2);

    // Send a 10-microsecond pulse to trigger the sound wave
    digitalWrite(TRIG_PIN, HIGH);
    delayMicroseconds(10);
    digitalWrite(TRIG_PIN, LOW);

    // --------------------------------------------------------
    // STEP 2: MEASURE THE ECHO
    // --------------------------------------------------------
    // pulseIn() waits for the ECHO_PIN to go HIGH,
    // then measures how long it stays HIGH.
    long duration = pulseIn(ECHO_PIN, HIGH);

    // --------------------------------------------------------
    // STEP 3: THE PHYSICS MATH
    // --------------------------------------------------------
    // Speed of sound is approximately
    // 0.034 centimeters per microsecond.
    //
    // We divide by 2 because the sound traveled:
    //
    // SENSOR -> OBJECT -> SENSOR
    //
    int distanceCm = duration * 0.034 / 2;

    // Print to Serial Monitor
    Serial.print("Distance: ");
    Serial.print(distanceCm);
    Serial.println(" cm");

    // --------------------------------------------------------
    // STEP 4: VISUAL WARNING LOGIC
    // --------------------------------------------------------

    if (distanceCm > 30) {
        // FAR AWAY (SAFE)
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, LOW);
        digitalWrite(LED_RED, LOW);
    }
    else if (distanceCm > 10 && distanceCm <= 30) {
        // GETTING CLOSER (WARNING)
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, HIGH);
        digitalWrite(LED_RED, LOW);
    }
    else {
        // TOO CLOSE (DANGER)
        digitalWrite(LED_GREEN, HIGH);
        digitalWrite(LED_YELLOW, HIGH);
        digitalWrite(LED_RED, HIGH);
    }

    // Wait before pinging again so echoes do not overlap
    delay(100);
}
Hardware Reminder

The code expects the HC-SR04 Echo signal reaching D18 to already be reduced to safe ESP32 logic voltage by the resistor divider shown in the Wiring section.

06 / Understand Code

Decode the Radar

Four important pieces turn a tiny pulse into a physical distance measurement.

μs

delayMicroseconds(10)

This creates a very short delay measured in microseconds. The HC-SR04 uses a roughly 10-microsecond HIGH trigger pulse to begin a measurement.

⏱

pulseIn(ECHO_PIN, HIGH)

This measures how long the Echo pin remains HIGH. The returned value is a duration in microseconds.

÷2

The Physics Math

Sound travels approximately 0.034 cm per microsecond. The measured time is divided by two because the sound makes a round trip.

⚠

Progressive Warnings

The if / else if / else structure changes the LED state based on the measured distance.

Why Divide by 2?

Imagine the sensor is 50 cm away from a wall. The ultrasonic pulse does not travel only 50 cm. It travels 50 cm toward the wall and another 50 cm back to the sensor.

Total travel: 100 cm .

Therefore, after calculating the total distance traveled by the sound, we divide it by two to estimate the one-way distance to the object.

Example

If the Echo duration were 100 μs:

100 × 0.034 = 3.4 cm of total sound travel.
3.4 ÷ 2 = 1.7 cm from the sensor.

09 / Experiment

Slow the Radar Down

Right now the radar performs roughly ten measurement cycles per second because the loop ends with delay(100).

Change the Update Speed

Find this line:

C++ 
delay(100);

Change it to:

C++ 
delay(2000);

Now the ESP32 waits about two seconds between measurements. The Serial Monitor becomes much quieter.

Fast Mode

delay(100) gives frequent measurements and is useful for moving objects.

Slow Mode

delay(2000) is useful when measurements do not need to happen constantly.

Think Like an Engineer

A distance sensor does not always need to run as fast as possible. A water-level monitor or slow environmental system might only need a reading every few seconds. Choosing the measurement rate is part of system design.

Your Objective

When an object gets closer than 10 cm, make the Red LED blink rapidly instead of staying solid.

  • Find the final else { } block in the distance logic.

  • Turn the Red LED OFF.

Hint

Important Trade-Off

Because the blinking challenge uses delay(), the ESP32 spends time waiting inside the danger block. That means the Serial Monitor will update more slowly while the emergency effect is running. That's okay for this challenge.

11 / Troubleshooting

When the Radar Lies

Ultrasonic sensors are simple, but sound reflection creates some interesting failure cases.

01

Always 0 cm or nonsense

Check the TRIG and ECHO wires. Make sure TRIG is on D5 and the Echo signal is reaching D18 through the voltage divider. Also make sure the sensor and ESP32 share a common ground.

02

Distance jumps wildly

Sound reflects differently from different materials. Soft, angled, or irregular objects can produce poor echoes. Try a flat hard surface such as a wall or book.

03

Sensor gets hot

Disconnect power immediately and inspect VCC and GND. Do not reverse the sensor's power connections.

04

ESP32 behaves strangely

Check that the HC-SR04 Echo output is not being connected directly to an ESP32 GPIO when the sensor is powered from 5 V. Verify the resistor divider.

Problem Check Why
0 cm TRIG / ECHO wiring The ESP32 may not be receiving a valid Echo pulse.
Random values Object angle / surface Reflected sound may not return cleanly to the receiver.
LEDs wrong D2 / D4 / D15 The code depends on the exact GPIO assignments.
ESP32 GPIO issue Echo voltage divider ESP32 GPIO is 3.3 V logic.
