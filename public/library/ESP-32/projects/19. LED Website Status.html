ESP32 → Website Status

Brooo, we are taking the smart-home dashboard one massive step further. ⚡ Your webpage will no longer blindly send commands. The ESP32 will actually report the state of its physical hardware back to the webpage.

OLD SYSTEM: > "My dashboard blindly sends commands."
NEW SYSTEM: > "My dashboard reflects the hardware state."
MISSION: > Establish the first two-way IoT status loop.

04 // HARDWARE

Wire the Hardware

LED safety: Use a 220–330Ω current-limiting resistor in series with the LED. A safe connection is D2 → resistor → LED long leg and LED short leg → GND.
LED

Physical Light

The LED is our output. The ESP32 will store whether it should currently be ON or OFF.

Connection ESP32
LED control D2
LED return GND
Button

Physical Input

The button uses INPUT_PULLUP . That means one side goes to D14 and the other side goes to GND.

Connection ESP32
Button signal D14
Button return GND 
ESP32              BREADBOARD

D2 ─────► 220–330Ω ─────► LED Long Leg
                           LED Short Leg
                               │
                               ▼
GND ───────────────────── [ BLUE GND RAIL ]

D14 ────────────────────► Button Leg
                          Button Opposite Leg
                               │
                               ▼
                        [ BLUE GND RAIL ]

ESP32 GND ─────────────► [ BLUE GND RAIL ]
Why INPUT_PULLUP? When the button is not pressed, the ESP32 reads HIGH. When you press the button, it connects the pin to GND and the ESP32 reads LOW.

06 // SOURCE CODE

Complete Code

Before uploading: Replace YOUR_WIFI_NAME and YOUR_PASSWORD with your local Wi-Fi credentials.
C++ · Arduino 
/*
 * ============================================================
 * MY BRO'S NINETEENTH ESP32 PROGRAM: DYNAMIC WEB STATUS
 * ============================================================
 */

#include <WiFi.h>
#include <WebServer.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

WebServer server(80);

const int LED_PIN = 2;
const int BUTTON_PIN = 14;

// Memory variables for our hardware toggle
int ledState = LOW;
int lastButtonState = HIGH;

// ============================================================
// 1. THE DYNAMIC HOMEPAGE
// ============================================================
void handle_Homepage() {
    String html = "<!DOCTYPE html><html><head><meta name=\"viewport\" content=\"width=device-width, initial-scale=1\">";

    // Add some simple CSS to center everything and make it look clean
    html += "<style>body { text-align: center; font-family: sans-serif; margin-top: 50px; }</style></head><body>";

    html += "<h1>ESP32 Status Tracker</h1>";

    // --------------------------------------------------------
    // THE DYNAMIC PART!
    // We check the variable, and build the HTML differently based on the truth!
    // --------------------------------------------------------
    if (ledState == HIGH) {
        html += "<h2>Current Status: <span style=\"color:green;\">ON 💡</span></h2>";
    } else {
        html += "<h2>Current Status: <span style=\"color:red;\">OFF ⚫</span></h2>";
    }

    // Add a single Web Toggle button
    html += "<br><a href=\"/toggle\"><button style=\"font-size:20px; padding:15px; background:black; color:white;\">TOGGLE LIGHT</button></a>";

    // Add a refresh button just in case someone pressed the physical button
    html += "<br><br><a href=\"/\"><button style=\"padding:10px;\">Refresh Status</button></a>";

    html += "</body></html>";

    // Send the freshly built page to the phone
    server.send(200, "text/html", html);
}

// ============================================================
// 2. THE WEB TOGGLE ROUTE
// ============================================================
void handle_Toggle() {
    // Flip the state! If it was LOW, make it HIGH. If HIGH, make it LOW.
    if (ledState == LOW) {
        ledState = HIGH;
    } else {
        ledState = LOW;
    }

    digitalWrite(LED_PIN, ledState);

    // Instantly bounce the user back to the homepage
    server.sendHeader("Location", "/");
    server.send(303);
}

// ============================================================
// SETUP
// ============================================================
void setup() {
    Serial.begin(115200);

    pinMode(LED_PIN, OUTPUT);
    pinMode(BUTTON_PIN, INPUT_PULLUP);

    WiFi.begin(ssid, password);
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }

    Serial.println("\n🔥 Wi-Fi Connected!");
    Serial.print("Open this IP: http://");
    Serial.println(WiFi.localIP());

    server.on("/", handle_Homepage);
    server.on("/toggle", handle_Toggle);
    server.begin();
}

// ============================================================
// LOOP
// ============================================================
void loop() {
    // 1. Listen for web visitors
    server.handleClient();

    // 2. Listen for the physical button!
    int currentButtonState = digitalRead(BUTTON_PIN);

    if (lastButtonState == HIGH && currentButtonState == LOW) {
        // Physical click detected! Flip the state.
        if (ledState == LOW) {
            ledState = HIGH;
        } else {
            ledState = LOW;
        }

        digitalWrite(LED_PIN, ledState);
        delay(50); // Tiny debounce
    }

    lastButtonState = currentButtonState;
}
Save with Ctrl + S before building.
07 // CODE BREAKDOWN

Understand the Code

Source of Truth

The Shared Variable

This variable is the central memory of the system:

C++ 
int ledState = LOW;

Both the web route and the physical button modify this same variable.

That gives us one logical source of truth for the LED state.

Dynamic HTML

The Page Is Built at Request Time

When the browser requests /, the ESP32 checks ledState and chooses which HTML to add.

C++ 
if (ledState == HIGH) {
    html += "ON";
} else {
    html += "OFF";
}
Web Route

/toggle

The browser visits:

URL path 
/toggle

The ESP32 flips the shared state, updates the physical LED, and redirects the browser back to the homepage.

Physical Input

Button Edge Detection

We compare the previous button state with the current state.

C++ 
if (lastButtonState == HIGH &&
    currentButtonState == LOW) {
    // New button press!
}

This prevents one held button from toggling repeatedly every loop.

Think like an engineer: The ESP32 is now acting as both a controller and a reporter. It receives commands, changes hardware, remembers state, and generates a representation of that state for the browser.

12 // DEBUG

Troubleshooting

Button

Physical button does nothing

Check that this line exists at the very bottom of the loop:

C++ 
lastButtonState = currentButtonState;

Without updating the previous state, the edge-detection logic cannot correctly track the button transition.

Status

Webpage does not update

This is expected after using the physical button.

The browser does not automatically know that the ESP32 changed. Tap Refresh Status or reload the homepage.

HTTP

Toggle page gets stuck

Check that the redirect has both:

C++ 
server.sendHeader("Location", "/");
server.send(303);
Wi-Fi

Phone cannot open the page

  • Check both devices are on the same Wi-Fi.
  • Verify the printed IP address.
  • Check your Wi-Fi credentials.
  • Make sure the ESP32 is still powered.
Security reminder: This is a local-network prototype. Do not expose the ESP32's control server directly to the public Internet without designing proper authentication, authorization, transport security, and network protections.

Source of Truth

GPIO State
