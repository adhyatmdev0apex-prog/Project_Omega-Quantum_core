🚨 LED SAFETY — DON'T SKIP THIS

Do not connect an LED directly to an ESP32 GPIO without current limiting. Put a 220–330Ω resistor in series with the LED. A safe connection is: D2 → resistor → LED long leg → LED short leg → GND.

03 / Core Concepts

What Are We Learning?

Project 27 is where web development starts touching physical electronics in a much more continuous way.

01

HTML Range Input

HTML has a built-in slider: <input type="range">. We will configure it from 0 to 255.

That gives us a convenient digital control for the ESP32's PWM brightness range.

02

Real-Time JavaScript Events

Instead of waiting for a button click with onclick, we use oninput.

As the slider moves, JavaScript receives the new value immediately.

03

URL Parameters

We attach data to a URL: ?val=150.

The ESP32 extracts that parameter and converts it back into a number.

04

PWM

PWM lets the ESP32 rapidly control the effective power delivered to the LED.

A value near 0 means very dim/off; a value near 255 means maximum brightness.

⚠️ Why the resistor?

The resistor limits current through the LED. It protects both the LED and the ESP32 GPIO from excessive current. Keep it in the circuit even though the project code controls brightness with PWM.

📌 Why D2?

We are keeping the familiar D2 LED pin from earlier projects. The Arduino ESP32 environment can generate PWM output with analogWrite().

06 / Firmware

Complete Code

Delete the default PlatformIO code and paste this complete program into src/main.cpp.

🚨 CRITICAL

Replace YOUR_WIFI_NAME and YOUR_PASSWORD with your actual Wi-Fi credentials before uploading.

C++ / src/main.cpp 
/*
 * ============================================================
 * MY BRO'S TWENTY-SEVENTH ESP32 PROGRAM: SMARTPHONE SLIDER
 * ============================================================
 */

#include <WiFi.h>
#include <WebServer.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

WebServer server(80);

const int LED_PIN = 2;

// ============================================================
// 1. THE HOMEPAGE (WITH JAVASCRIPT SLIDER)
// ============================================================
void handle_Homepage() {
    String html = "<!DOCTYPE html><html><head><meta name=\"viewport\" content=\"width=device-width, initial-scale=1\">";

    // Some CSS to make the slider look huge and easy to touch on a phone
    html += "<style>";
    html += "body { font-family: sans-serif; text-align: center; margin-top: 50px; background-color: #111; color: #fff; }";
    html += "input[type=range] { width: 80%; margin: 40px 0; }";
    html += "</style>";

    // --------------------------------------------------------
    // JAVASCRIPT
    // --------------------------------------------------------
    html += "<script>";
    html += "function updateBrightness(sliderValue) {";

    // Update the text on the screen so the user sees the number
    html += "  document.getElementById('brightness_text').innerHTML = sliderValue;";

    // Fetch the URL with the parameter attached! (e.g., /set_pwm?val=200)
    html += "  fetch('/set_pwm?val=' + sliderValue);";
    html += "}";
    html += "</script>";
    // --------------------------------------------------------

    html += "</head><body>";
    html += "<h1>🎚️ Wireless Dimmer</h1>";

    html += "<h2>Brightness: <span id=\"brightness_text\" style=\"color:#00ffcc;\">0</span></h2>";

    // THE HTML SLIDER!
    // min="0", max="255".
    // oninput triggers our JS function every time the finger moves!
    html += "<input type=\"range\" min=\"0\" max=\"255\" value=\"0\" oninput=\"updateBrightness(this.value)\">";

    html += "</body></html>";

    server.send(200, "text/html", html);
}

// ============================================================
// 2. THE BACKGROUND ROUTE (CATCHING THE URL PARAMETER)
// ============================================================
void handle_SetPWM() {
    // Check if the URL actually contains "?val="
    if (server.hasArg("val")) {

        // Extract the value and convert it from text into a math integer
        String valueText = server.arg("val");
        int pwmValue = valueText.toInt();

        // Output that power to the physical LED!
        analogWrite(LED_PIN, pwmValue);

        Serial.print("Remote Command Received. Brightness set to: ");
        Serial.println(pwmValue);
    }

    // Send a tiny empty response back so the phone knows we got it
    server.send(200, "text/plain", "OK");
}

// ============================================================
// SETUP & LOOP
// ============================================================
void setup() {
    Serial.begin(115200);

    pinMode(LED_PIN, OUTPUT);
    analogWrite(LED_PIN, 0); // Start with LED off

    WiFi.begin(ssid, password);

    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }

    Serial.println("\n🔥 Wi-Fi Connected!");
    Serial.print("Open this IP on your phone: http://");
    Serial.println(WiFi.localIP());

    server.on("/", handle_Homepage);
    server.on("/set_pwm", handle_SetPWM); // Register the new route!

    server.begin();
}

void loop() {
    server.handleClient();
}
🔬 What just happened?

Your ESP32 is simultaneously running a web server and controlling a physical PWM output. The browser sends numbers; the ESP32 interprets those numbers as brightness.

07 / Code Anatomy

Understand the Code

This is the bridge between three different worlds: HTML, JavaScript, and C++.

🎚️ <input type="range">

HTML creates the draggable slider.

We set:

min = 0 max = 255 value = 0

So the browser gives us exactly the range we need for the brightness control.

⚡ oninput

onclick waits for a click.

oninput reacts while the value is being changed.

That makes it perfect for a slider.

🌐 URL Construction

JavaScript creates:

/set_pwm?val=127

The part before the question mark is the route. The part after it contains our parameter.

🧠 server.arg()

The ESP32 receives the parameter as text.

"127"

Then toInt() converts that text into the integer:

127

🔁 The complete data journey

Finger moves → Slider = 127 → fetch() → /set_pwm?val=127 → server.arg("val") → toInt() → analogWrite()
💡 This is a real client-server architecture

The smartphone browser is the client. It requests an action. The ESP32 is the server. It receives the request, parses the value, and changes physical hardware.

⚠️ "Real-time" does not mean zero latency

Every slider movement still requires an HTTP request, Wi-Fi transmission, ESP32 processing, and PWM update. The system can feel very responsive, but there is always some network and processing latency.

10 / Experiment

Experiment — Limit the Slider

Let's deliberately change the limits of the remote. This teaches you that the browser itself can enforce part of the control range.

🧪 Change this

HTML 
<input type="range" min="0" max="255" value="0">

Change the maximum from 255 to 50:

HTML 
<input type="range" min="0" max="50" value="0">

Before

0 ───────────────► 255 OFF FULL

The slider can send values across the entire 0–255 PWM range.

After

0 ───► 50 OFF LOW LIMIT

The browser now limits the slider to 50, so maximum requested brightness is much lower.

⚠️ Engineering lesson

UI limits can be useful, but do not treat client-side limits as a complete safety mechanism. A user can alter browser requests manually. A real safety-critical system should validate limits on the ESP32/server side too.

🔬 Bonus experiment

Try setting the maximum to 10, 100, and 255. Compare how the physical brightness changes.

12 / Debugging

Troubleshooting

Don't panic if the first upload doesn't behave perfectly. Debug the system layer by layer.

Problem Likely Cause Check
LED doesn't dim Wrong GPIO or wiring Verify LED is connected to D2 through a 220–330Ω resistor.
Slider moves but LED does nothing HTTP request isn't reaching the route Watch Serial Monitor for "Remote Command Received".
No Serial messages Wrong fetch URL or network problem Check /set_pwm?val=... exactly.
Phone cannot open page Network connectivity issue Confirm phone can reach the ESP32's local IP.
Wi-Fi never connects Wrong credentials or unsupported network Check SSID/password and use a compatible 2.4 GHz network.
LED is always ON LED wiring or PWM output issue Verify LED polarity, resistor, D2 connection, and GND.
Compilation error at toInt() Wrong variable type or modified code Keep server.arg("val") in a String before calling toInt().
🚨 If the LED is connected directly to D2

Stop and add the current-limiting resistor. The correct path is: D2 → 220–330Ω resistor → LED → GND.

🔍 Debug like an engineer

Is ESP32 powered? → Is Wi-Fi connected? → Does browser load? → Does fetch reach ESP32? → Does PWM change? → Does LED respond?

Never change five things at once. Find the first stage where the signal stops, then debug that stage.
