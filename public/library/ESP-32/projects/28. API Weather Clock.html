The API Weather Clock

Your ESP32 is no longer just waiting for your phone. Today, it reaches out into the open internet, requests live weather data, parses JSON, and displays the result on a physical OLED screen.

my-bro@esp32:~$ connect-to-world --api --oled

Today we flip the script.

Your ESP32 becomes the client. It independently asks an internet server for information and brings that information back to your hardware.
🌐

03 // CONCEPTS

What Are We Learning?

Three major concepts turn the ESP32 from a local controller into an internet-connected computing device.

🌐

1. What Is an API?

API stands for Application Programming Interface .

Think of an API as a special internet endpoint designed for programs to request data.

A normal website is designed for humans. An API response is designed to be easily processed by software.

📨

2. HTTP GET Requests

In Projects 17–27, we used WebServer to make the ESP32 listen for requests.

Now we use HTTPClient so the ESP32 can make requests itself.

It sends a GET request to the weather API and waits for the server's response.

📦

3. Parsing JSON

In Project 22, the ESP32 created JSON data for your browser.

Today we do the opposite: receive JSON and unpack it.

The ArduinoJson library lets us extract values such as temperature and wind speed.

06 // FIRMWARE

Complete Code

Delete the default PlatformIO code and paste the complete program below.

🚨 CRITICAL — WIFI DETAILS

Replace YOUR_WIFI_NAME and YOUR_PASSWORD with your actual 2.4 GHz Wi-Fi credentials.

Do not publish real Wi-Fi credentials in a public Git repository.

🌦️ WEATHER LOCATION

The example API URL starts with London coordinates. We will change those coordinates later in the Experiment section.

C++ 
/*
 * ============================================================
 * MY BRO'S TWENTY-EIGHTH ESP32 PROGRAM: LIVE WEATHER API
 * ============================================================
 */

#include <WiFi.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

// Open-Meteo coordinates for London
String weatherAPI =
    "http://api.open-meteo.com/v1/forecast?"
    "latitude=51.5085&longitude=-0.1257"
    "&current_weather=true";

// Setup OLED
Adafruit_SSD1306 display(128, 64, &Wire, -1);

// Timer variables
unsigned long previousMillis = 0;
const long interval = 10000;

void setup() {
    Serial.begin(115200);

    // 1. BOOT OLED
    if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
        for (;;) {
        }
    }

    display.clearDisplay();
    display.setTextColor(WHITE);
    display.setTextSize(2);
    display.setCursor(0, 20);
    display.println("WIFI...");
    display.display();

    // 2. CONNECT TO WI-FI
    WiFi.begin(ssid, password);

    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
    }

    Serial.println("\n🔥 Wi-Fi Connected!");

    display.clearDisplay();
    display.setCursor(0, 20);
    display.println("CONNECTED!");
    display.display();
}

void loop() {
    unsigned long currentMillis = millis();

    // --------------------------------------------------------
    // THE API FETCH TIMER
    // --------------------------------------------------------
    if (
        currentMillis - previousMillis >= interval ||
        previousMillis == 0
    ) {
        previousMillis = currentMillis;

        // Check if Wi-Fi is still alive
        if (WiFi.status() == WL_CONNECTED) {

            Serial.println(
                "🌐 Connecting to Weather API..."
            );

            // 1. CREATE HTTP CLIENT
            HTTPClient http;

            // 2. OPEN THE API URL
            http.begin(weatherAPI);

            // 3. SEND HTTP GET REQUEST
            int httpResponseCode = http.GET();

            // 4. CHECK SERVER RESPONSE
            if (httpResponseCode == 200) {

                // Download the JSON response
                String payload = http.getString();

                // 5. CREATE JSON DOCUMENT
                JsonDocument doc;

                // Parse the JSON response
                deserializeJson(doc, payload);

                // Extract the values we want
                float temperature =
                    doc["current_weather"]["temperature"];

                float windSpeed =
                    doc["current_weather"]["windspeed"];

                Serial.print("Success! Temp: ");
                Serial.println(temperature);

                // 6. UPDATE OLED
                display.clearDisplay();

                display.setTextSize(1);
                display.setCursor(0, 0);
                display.println(
                    "LIVE WEATHER (LONDON)"
                );

                display.drawLine(
                    0,
                    10,
                    128,
                    10,
                    WHITE
                );

                // Temperature
                display.setTextSize(3);
                display.setCursor(0, 20);
                display.print(temperature);

                display.setTextSize(1);
                display.print(" C");

                // Wind
                display.setCursor(0, 50);
                display.print("Wind: ");
                display.print(windSpeed);
                display.print(" km/h");

                display.display();

            } else {

                Serial.print("Error code: ");
                Serial.println(httpResponseCode);
            }

            // 7. CLOSE HTTP CONNECTION
            http.end();
        }
    }
}

💡 WHAT THIS PROGRAM DOES

The ESP32 connects to Wi-Fi, waits ten seconds between API requests, downloads JSON from Open-Meteo, extracts temperature and wind speed, and renders them on the OLED.

07 // CODE ARCHITECTURE

Understand the Code

This is the same basic architecture used by many internet-connected applications: request → response → parse → display.

HTTPClient http;

Creates an HTTP client object that lets the ESP32 communicate with a web server.

Think of it as the networking machinery used to make an outgoing web request.

http.GET();

Sends an HTTP GET request to the URL configured with http.begin() .

The server then sends a response back.

HTTP Status Code

The return value tells us what happened.

  • 200 — request succeeded.
  • 404 — resource not found.
  • Negative values can indicate a connection-level failure.

deserializeJson()

Converts the raw JSON response into a structure that ArduinoJson can navigate.

Instead of manually searching through a giant text string, we can access named fields directly.

JSON 
{
    "current_weather": {
        "temperature": 24.5,
        "windspeed": 12.3
    }
}

🔎 The JSON Path

This expression:

C++ 
doc["current_weather"]["temperature"]

means:

doc
→
current_weather
→
temperature
→
24.5

⏱️ WHY USE MILLIS?

Instead of putting delay(10000) around the entire loop, we use millis() to decide when the next API request is due. This leaves the main loop available for other work between requests.

⚠️ API REQUESTS ARE NOT FREE

Do not continuously hammer a public API with thousands of requests per second. APIs can impose rate limits, reject abusive traffic, or temporarily block clients. A ten-second interval is only a beginner demonstration; production systems should follow the API's documented usage limits.

On-Demand Weather Button

Right now the ESP32 automatically asks the API every ten seconds. Let's make the weather update happen only when you request it.

🎯 OBJECTIVE

Turn the ESP32 into an on-demand weather pager . Press a physical button and only then make the API request.

Requirements

1

Add a Push Button

Connect a push button to D14.

One side of the button goes to D14. The opposite side goes to GND.

2

Enable INPUT_PULLUP

Add:

C++ 
pinMode(14, INPUT_PULLUP);
3

Remove the Timer Trigger

Remove the millis() condition that decides when the API request happens.

4

Add Button Memory

Create a lastButtonState variable so the ESP32 detects a new button press rather than repeatedly treating a held button as many presses.

5

Trigger the API Request

Run the weather-fetch logic when the button changes from HIGH to LOW.

6

Add Debouncing

Use a small debounce delay or, preferably in a later project, a non-blocking debounce technique.

Logic Hint 
int currentButtonState = digitalRead(14);

if (lastButtonState == HIGH &&
    currentButtonState == LOW) {

    // YOUR WEATHER FETCH LOGIC HERE

    delay(50);
}

lastButtonState = currentButtonState;

12 // DEBUGGING

Troubleshooting

Internet projects introduce a whole new class of failure points: hardware, Wi-Fi, DNS, HTTP, API availability, JSON parsing, and display output.

❌ Error code: -1

The HTTP connection failed before a normal HTTP response was received.

  • Check Wi-Fi connection.
  • Check whether the network actually has internet access.
  • Check the API URL.
  • Check whether DNS/network access is working.

❌ OLED Says CONNECTED!

The ESP32 joined Wi-Fi, but the API request may not be succeeding.

  • Open Serial Monitor.
  • Look for Connecting to Weather API...
  • Check the HTTP response code.

❌ OLED Is Completely Dark

Check the I2C wiring.

  • VCC → 3V3
  • GND → GND
  • SDA → D21
  • SCL → D22

❌ OLED Init Fails

The code currently uses I2C address 0x3C .

Some OLED modules use 0x3D instead.

❌ ArduinoJson Errors

Make sure the ArduinoJson library is actually listed in lib_deps .

❌ Wi-Fi Never Connects

Remember that the ESP32 DevKit V1 uses 2.4 GHz Wi-Fi for this project.

Also check that your SSID and password are case-sensitive and correctly entered.

⚠️ IMPORTANT ABOUT HTTPS

This beginner project uses an HTTP endpoint to keep TLS certificate handling out of the first API lesson. In real-world applications, sensitive information should be transferred over HTTPS.

13 // KNOWLEDGE

New Vocabulary

These words are going to appear constantly as you move deeper into IoT and networking.

Word Meaning
API Application Programming Interface. A defined interface that lets software request or exchange information with another system.
HTTP GET An HTTP request method commonly used to ask a server for a resource or information.
JSON JavaScript Object Notation. A structured text format commonly used for exchanging data between software systems.
Deserialization Converting serialized data such as JSON text into a structured form that a program can work with.
Client A device or program that requests information or services from another system.
HTTP Status Code A number returned by an HTTP server describing the result of a request, such as 200 or 404.
Endpoint A specific network location where a service accepts requests.
