EMAIL ALERTS
VIA IFTTT

Your ESP32 is no longer just logging data. Today it becomes an event-driven notification system that can trigger a real email through the Internet.

EVENT → WEBHOOK → IFTTT → EMAIL

From silent sensor to active alarm 🚨

In Project 29, your ESP32 pushed sensor readings into the cloud. That was useful, but you still had to open the dashboard and look at the data. Now we reverse the idea.

The mission

Press a physical button on the ESP32. The board sends an HTTP request to an IFTTT Webhook. IFTTT receives the event and triggers an email notification.

🔘 BUTTON PRESSED
🟢 ESP32 DETECTS EVENT
🌐 HTTP WEBHOOK REQUEST
☁️ IFTTT RECEIVES EVENT
📧 EMAIL IS TRIGGERED
Important idea

The ESP32 does not directly log into your Gmail account and send an email. Instead, it sends a request to IFTTT, and IFTTT performs the notification action.

🔌 Wiring

The button uses the same INPUT_PULLUP technique you learned earlier. One side goes to D14 and the other goes to ground.

Connections

D14 Button leg
GND Blue GND rail
Button Opposite leg → GND
INPUT_PULLUP

When the button is not pressed, the GPIO reads HIGH. When pressed, the button connects the GPIO to GND and the GPIO reads LOW.

Breadboard diagram

ESP32 BREADBOARD D14 ────────────────► [ BUTTON ] │ │ ▼ [ Blue GND Rail ] ▲ │ GND ────────────────────┘ INPUT_PULLUP Not pressed = HIGH Pressed = LOW
Tactile button orientation

Many four-leg tactile switches have internally connected pairs of legs. If your button behaves strangely, rotate it by 90° or verify its internal pin arrangement.

📄 Complete Code

This is the complete Project 30 program. Replace the Wi-Fi placeholders and your IFTTT Webhook key before uploading.

Critical

Replace YOUR_WIFI_NAME, YOUR_PASSWORD, and YOUR_SECRET_IFTTT_KEY. Keep the real key private.

C++ 
/*
 * ============================================================
 * MY BRO'S THIRTIETH ESP32 PROGRAM: IFTTT EMAIL ALERTS
 * ============================================================
 */

#include <WiFi.h>
#include <HTTPClient.h>

// 1. YOUR NETWORK DETAILS
const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

// 2. YOUR IFTTT DETAILS
// The exact Event Name created in IFTTT
String eventName = "esp32_alert";

// Paste your secret Webhook key here
String iftttKey = "YOUR_SECRET_IFTTT_KEY";

const int BUTTON_PIN = 14;

int lastButtonState = HIGH;

void setup() {
    Serial.begin(115200);

    pinMode(BUTTON_PIN, INPUT_PULLUP);

    Serial.print("Connecting to Wi-Fi");

    WiFi.begin(ssid, password);

    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }

    Serial.println("\n🔥 Wi-Fi Connected! Armed and ready.");
}

void loop() {

    int currentButtonState = digitalRead(BUTTON_PIN);

    // Check if the button was just pressed
    if (lastButtonState == HIGH && currentButtonState == LOW) {

        Serial.println("\n🚨 ALARM TRIGGERED! Button Pressed!");

        if (WiFi.status() == WL_CONNECTED) {

            HTTPClient http;

            // Build the Webhook URL.
            // value1 carries our custom message.
            String url =
                "http://maker.ifttt.com/trigger/" +
                eventName +
                "/with/key/" +
                iftttKey +
                "?value1=PANIC_BUTTON_PRESSED";

            Serial.println(
                "🌐 Tripping the IFTTT Webhook..."
            );

            http.begin(url);

            // Send the HTTP GET request.
            int httpCode = http.GET();

            // IFTTT should return HTTP 200 for a
            // successfully accepted Webhook request.
            if (httpCode == 200) {

                String response = http.getString();

                Serial.println(
                    "✅ IFTTT Webhook accepted!"
                );

                Serial.print("Server response: ");
                Serial.println(response);

            } else {

                Serial.print(
                    "❌ Failed to send! HTTP Code: "
                );

                Serial.println(httpCode);
            }

            http.end();

        } else {

            Serial.println(
                "❌ Wi-Fi disconnected. Cannot send alert."
            );
        }

        // Simple beginner debounce / spam protection.
        delay(2000);
    }

    lastButtonState = currentButtonState;
}
Why 2000 ms?

The two-second delay gives the button time to settle and prevents repeated triggers during this beginner experiment. It is a simple blocking debounce/spam-prevention technique. Later, you can replace it with fully non-blocking timing using millis().

🧠 Understand the Code

The most important part of this project is not the button. It is the path from a local hardware event to a cloud automation service.

The Webhook URL

URL Structure 
http://maker.ifttt.com/trigger/esp32_alert/with/key/YOUR_SECRET_KEY?value1=PANIC_BUTTON_PRESSED

This URL contains several pieces of information.

Part Meaning
trigger Tells IFTTT that we are triggering an event.
esp32_alert The event name created in the IFTTT Applet.
with/key/... Supplies the secret Webhook key used for authorization.
?value1=... Attaches custom data to the event.
The event flow
🔘 GPIO D14 changes HIGH → LOW
🧠 ESP32 recognizes a button press
🧱 Code constructs the Webhook URL
🌐 HTTPClient sends GET request
☁️ IFTTT receives the event
📧 IFTTT performs the configured email action
http.GET()

Sends the HTTP GET request to the Webhook endpoint.

httpCode

Stores the HTTP response status returned by the server.

http.end()

Closes the HTTP connection and releases associated resources.

lastButtonState

Lets the program detect the transition from not pressed to pressed rather than repeatedly treating a held button as a new event.

HTTP success is not email delivery

An HTTP 200 response means the Webhook request was successfully accepted by the endpoint. It does not guarantee that an email has already reached the inbox. Email delivery happens after IFTTT processes the event.

Why underscores?

A URL query parameter needs properly encoded data. Ordinary spaces should not simply be inserted into a raw URL. For this beginner experiment, underscores are the easiest way to separate words.

Panic

value1=PANIC_BUTTON_PRESSED

Door

value1=FRONT_DOOR_OPENED

Custom

Create your own event message.

Better URL encoding

In production code, arbitrary text should be URL-encoded correctly rather than relying on underscores. This experiment keeps the beginner implementation simple.

🔥 Challenge — Server Room Overheat Alarm

Now combine the sensor logic from Project 29 with the cloud event logic from Project 30.

Your objective

Build a system that checks a DHT11 every 10 seconds. If the temperature rises above 30°C, the ESP32 should trigger an IFTTT email alert.

Requirements
  • Wire the DHT11 from Project 29.
  • Remove the physical button logic from the main event loop.
  • Use millis() to check the sensor every 10 seconds.
  • Read the temperature into a variable called temp.
  • Trigger IFTTT when temp > 30.
  • Pass the temperature into value1.
  • Create a boolean variable called alarmSent.
  • Set alarmSent = true after a successful alarm.
  • Do not repeatedly send alerts while the room remains above the threshold.
  • Reset alarmSent after the temperature returns to a safe level.
Core logic
C++ 
bool alarmSent = false;

if (temp > 30 && alarmSent == false) {

    // Trigger IFTTT here.

    alarmSent = true;
}

if (temp <= 30) {
    alarmSent = false;
}
Why alarmSent matters

Without this state variable, a temperature check every 10 seconds could trigger another email every 10 seconds while the temperature remains above the threshold. The boolean gives the system memory.

Extra upgrade

Instead of sending only 30, send a message such as:

Payload idea 
?value1=Temperature_Exceeded_30C

🐛 Troubleshooting

Cloud projects have multiple failure points. Debug them from the ESP32 outward.

Problem Likely Cause Fix
HTTP 400 Bad request or malformed event parameters. Check the URL construction and event name.
HTTP 401 Authorization/key problem. Verify the IFTTT Webhook key.
Wrong event Event name mismatch. Make sure esp32_alert exactly matches the IFTTT event.
HTTP success but no email IFTTT action or email delivery issue. Check the IFTTT Applet, connected email account, and Spam/Junk folder.
Button does nothing Incorrect wiring or wrong button orientation. Verify D14 → button → GND and INPUT_PULLUP.
Button triggers repeatedly Mechanical bounce or repeated event detection. The current two-second delay is simple debounce/spam protection.
URL payload fails Unencoded characters such as spaces. Use URL-safe text or proper percent-encoding.
Wi-Fi never connects Wrong credentials or unavailable network. Verify SSID/password and network availability.
Security troubleshooting

If your Webhook key or Wi-Fi password was accidentally published, treat it as exposed. Rotate/revoke the credential where supported and replace it in your local project.

🧠 New Vocabulary

These four concepts are the real knowledge behind today's project.

Webhook

A custom HTTP endpoint that lets one system notify another system that an event occurred.

Event-Driven

An architecture where an action occurs in response to a specific event or trigger.

Payload / Cargo

Additional data carried alongside a request. In this project, value1 carries our custom message.

API Key

A secret credential used by a service to identify or authorize a client request.

One-line mental model
Event → Request → Automation → Action

The button creates the event. The ESP32 creates the request. IFTTT performs the automation. The email is the resulting action.
