Until now, every firmware update required a physical USB connection. Today, your ESP32 learns how to receive compatible firmware updates over Wi-Fi using OTA — Over-The-Air updates.

USB FLASHING → WI-FI FLASHING

From tethered hardware to wireless deployment 📡

Imagine an ESP32 mounted outside as a weather station. Or installed high on a wall. Or attached to a machine where reaching the USB port is annoying.

The mission

First, upload a special seed program over USB. That program connects the ESP32 to Wi-Fi and starts the OTA listener. After that, PlatformIO can send new firmware wirelessly to the board.

💻
LAPTOP
Compiles the new firmware and sends it through the network.
📡
WI-FI NETWORK
Carries the compiled firmware from the computer to the ESP32.
🟦
ESP32
Receives the update, writes it to the OTA application partition, and reboots.

The USB cable isn't gone forever

OTA removes the need for USB during normal wireless deployment, but USB remains an important recovery path for first-time setup, network changes, or firmware that can no longer run the OTA service.

🧠 What Are We Learning?

Three concepts make today's wireless deployment system work.

🌱
1. The Seed Program

The ESP32 does not magically accept OTA updates from a blank firmware image. A compatible application must first be installed that initializes networking and the OTA service.

📛
2. mDNS

Multicast DNS can advertise a hostname such as quantum-esp32.local on a local network, making the device easier to discover without manually remembering its current IP address.

🚪
3. ArduinoOTA.handle()

The OTA service needs regular processing through ArduinoOTA.handle() inside the main loop.

💾
4. Firmware Flashing

PlatformIO compiles your source code into firmware, then the OTA process transfers that compiled image to the ESP32.

Mental model
🌱 USB installs the OTA-capable seed
📡 ESP32 joins Wi-Fi
🚪 OTA service listens for updates
💻 PlatformIO sends new firmware
🔄 ESP32 installs and reboots

📄 Complete Code — The Seed Program

This is the program that plants the OTA capability onto the ESP32.

Replace your Wi-Fi credentials

Replace the Wi-Fi placeholders before building. Never publish real passwords in a public repository.

C++ 
/*
 * ============================================================
 * MY BRO'S THIRTY-FIRST ESP32 PROGRAM: OTA UPDATES
 * ============================================================
 */

#include <WiFi.h>
#include <ESPmDNS.h>
#include <WiFiUdp.h>
#include <ArduinoOTA.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_PASSWORD";

const int LED_PIN = 2;

void setup() {

    Serial.begin(115200);

    pinMode(LED_PIN, OUTPUT);

    // 1. CONNECT TO WI-FI
    Serial.println("Booting...");

    WiFi.mode(WIFI_STA);

    WiFi.begin(
        ssid,
        password
    );

    while (
        WiFi.waitForConnectResult() !=
        WL_CONNECTED
    ) {

        Serial.println(
            "Wi-Fi Connection Failed! Rebooting..."
        );

        delay(5000);

        ESP.restart();
    }


    // 2. CONFIGURE OTA SETTINGS

    ArduinoOTA.setHostname(
        "quantum-esp32"
    );


    ArduinoOTA.onStart(
        []() {

            Serial.println(
                "\n🚀 OTA Update Starting..."
            );

        }
    );


    ArduinoOTA.onEnd(
        []() {

            Serial.println(
                "\n✅ OTA Update Complete!"
            );

        }
    );


    ArduinoOTA.onProgress(
        [](unsigned int progress,
           unsigned int total) {

            Serial.printf(
                "Progress: %u%%\r",
                (progress / (total / 100))
            );

        }
    );


    // 3. START OTA LISTENER

    ArduinoOTA.begin();


    Serial.println(
        "\n🔥 System Ready for Wireless Updates!"
    );

    Serial.print(
        "IP Address: "
    );

    Serial.println(
        WiFi.localIP()
    );

    Serial.print(
        "Hostname: "
    );

    Serial.println(
        "quantum-esp32.local"
    );
}


void loop() {

    // 4. PROCESS OTA REQUESTS
    ArduinoOTA.handle();


    // Simple heartbeat
    digitalWrite(
        LED_PIN,
        HIGH
    );

    delay(100);

    digitalWrite(
        LED_PIN,
        LOW
    );

    delay(1000);
}
One line you absolutely need

The most important line for the OTA loop is: ArduinoOTA.handle();. If your running firmware does not process the OTA service, it cannot respond to OTA upload requests.

What the seed actually does

It connects to Wi-Fi, configures the OTA service, assigns a hostname, starts the OTA listener, and repeatedly services that listener from loop().

The OTA rule

Any firmware you upload wirelessly must itself continue to provide a working OTA path if you want future wireless updates. If you replace the OTA-capable firmware with a program that does not initialize the OTA service, the board may no longer be reachable through OTA.

Production thinking

A real deployed product normally needs more than this beginner OTA setup: authentication, robust update validation, rollback/recovery, secure transport, version management, and protection against interrupted or malicious updates.

🔥 Challenge — Secure OTA

An OTA service exposed to a network should not blindly accept firmware from every device that can reach it.

Your objective

Add password authentication to the OTA service and configure PlatformIO to provide the same password during upload.

Step 1 — Add the OTA password

    "CHANGE_THIS_PASSWORD"
);

Step 2 — Configure PlatformIO
INI

upload_port = 192.168.1.50

🐛 Troubleshooting

OTA depends on several things working together: power, Wi-Fi, IP addressing, firewall rules, firmware, and the upload configuration.

Problem Likely Cause Fix
Upload timeout Firewall or network connectivity is blocking the OTA connection. Check Windows Defender Firewall, network connectivity, and whether the ESP32 is reachable.
Board cannot be reached The ESP32's IP address may have changed. Check the current IP address or try the mDNS hostname if supported by your network.
mDNS hostname fails Your computer or network may not resolve .local hostnames correctly. Use the ESP32's current IP address instead.
OTA service disappeared The currently running firmware does not initialize or service OTA. Recover over USB and reinstall an OTA-capable firmware.
Wrong password ESP32 OTA password and PlatformIO authentication flag do not match. Make both values identical.
ESP32 keeps disconnecting Weak Wi-Fi signal or unstable power. Move the board closer to the access point and verify the USB wall adapter provides stable power.
Upload works but new program does not stay available The new firmware may not include the OTA setup. Make sure the replacement firmware also initializes and services OTA.
Firewall rule

If Windows asks whether Python, PlatformIO, or a related development process should be allowed through the firewall, allow network access on your trusted Private network when appropriate. Do not blindly expose development services to public networks.

🧠 New Vocabulary

These are the terms you should remember from this project.

OTA

Over-The-Air. Updating firmware through a network instead of a physical programming connection.

mDNS

Multicast DNS. A local-network discovery mechanism that lets devices advertise and resolve names such as quantum-esp32.local.

Binary

The compiled firmware image produced from your source code and transferred to the ESP32 during an update.

Firmware

Software stored on a microcontroller that controls how its hardware operates.

Network Flashing

Programming a device by transferring firmware through a network connection.

Authentication

Verifying that a client is authorized before allowing an operation such as an OTA update.
