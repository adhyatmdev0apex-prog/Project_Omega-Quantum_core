02 // CONCEPT

What Are We Learning?

Today we're stepping from beginner Arduino programming into operating-system-level task scheduling.

🧩

FreeRTOS

FreeRTOS is the real-time operating-system layer used by ESP32 software. It provides tasks, priorities, scheduling, delays, synchronization, and other RTOS primitives.

🧵

Tasks

A FreeRTOS task is an independently scheduled unit of work with its own stack and priority. Think of it as a managed worker inside the OS.

🎯

Core Pinning

A pinned task is restricted to a selected CPU core. That lets us deliberately control where specific work executes.

Key idea: Multitasking does not always mean two things are physically executing at the exact same instant. On a dual-core ESP32, tasks can genuinely execute concurrently when they are scheduled on separate cores, while multiple tasks on one core are still interleaved by the scheduler.

⏱️ vTaskDelay()

This tells FreeRTOS that the current task should sleep for a period of time. The task stops consuming CPU time while it waits, allowing other work to run.

🐕 Watchdog Timer

A watchdog monitors system responsiveness. If software prevents required watchdog service for too long, the system can trigger a reset. It is a recovery mechanism, not simply a detector of the delay() function.

06 // CODE

Complete Code

This is the heart of the project. Notice something strange at the bottom: loop() does practically nothing.

C++ // ESP32 
/*
 * ============================================================
 * MY BRO'S THIRTY-FOURTH ESP32 PROGRAM: DUAL-CORE FREERTOS
 * ============================================================
 */

#include <Arduino.h>

const int LED_CORE_0 = 2;
const int LED_CORE_1 = 4;

// Handles let FreeRTOS keep track of our tasks.
TaskHandle_t Task1;
TaskHandle_t Task2;

// ============================================================
// TASK 1: PINNED TO CORE 0
// ============================================================
void Task1code(void *pvParameters) {

    Serial.print("Task 1 is initializing on Core: ");
    Serial.println(xPortGetCoreID());

    for (;;) {

        digitalWrite(LED_CORE_0, HIGH);

        // Put THIS task to sleep for 1 second.
        vTaskDelay(1000 / portTICK_PERIOD_MS);

        digitalWrite(LED_CORE_0, LOW);

        vTaskDelay(1000 / portTICK_PERIOD_MS);
    }
}

// ============================================================
// TASK 2: PINNED TO CORE 1
// ============================================================
void Task2code(void *pvParameters) {

    Serial.print("Task 2 is initializing on Core: ");
    Serial.println(xPortGetCoreID());

    for (;;) {

        digitalWrite(LED_CORE_1, HIGH);

        // Put THIS task to sleep for 200 ms.
        vTaskDelay(200 / portTICK_PERIOD_MS);

        digitalWrite(LED_CORE_1, LOW);

        vTaskDelay(200 / portTICK_PERIOD_MS);
    }
}

// ============================================================
// SETUP
// ============================================================
void setup() {

    Serial.begin(115200);

    pinMode(LED_CORE_0, OUTPUT);
    pinMode(LED_CORE_1, OUTPUT);

    digitalWrite(LED_CORE_0, LOW);
    digitalWrite(LED_CORE_1, LOW);

    Serial.println("\nBooting Dual-Core Engine...");

    // --------------------------------------------------------
    // CREATE TASK 1
    // --------------------------------------------------------
    xTaskCreatePinnedToCore(
        Task1code,              // Task function
        "Task1",                // Task name
        10000,                  // Stack size
        NULL,                   // Parameters
        1,                      // Priority
        &Task1,                 // Task handle
        0                       // Core 0
    );

    // --------------------------------------------------------
    // CREATE TASK 2
    // --------------------------------------------------------
    xTaskCreatePinnedToCore(
        Task2code,              // Task function
        "Task2",                // Task name
        10000,                  // Stack size
        NULL,                   // Parameters
        1,                      // Priority
        &Task2,                 // Task handle
        1                       // Core 1
    );
}

// ============================================================
// ARDUINO LOOP
// ============================================================
void loop() {

    // The two FreeRTOS tasks are doing the actual work.
    // This loop intentionally has nothing important to do.

}
🔥 Notice the architecture: setup() creates the tasks. Each task then owns its own infinite for (;;) loop. FreeRTOS schedules those tasks after creation.
07 // DEEP DIVE

Understand the Code

Let's decode the important FreeRTOS pieces instead of blindly copying them.

xPortGetCoreID()

This returns the CPU core on which the calling task is currently executing.

C++ 
Serial.println(xPortGetCoreID());

for(;;)

This is an infinite loop:

C++ 
for (;;) {
    // task work
}

A task normally needs to remain alive instead of simply reaching the end of its function.

vTaskDelay()

The task becomes blocked for the requested number of RTOS ticks. Other schedulable work can use the CPU while this task waits.

C++ 
vTaskDelay(1000 / portTICK_PERIOD_MS);

xTaskCreatePinnedToCore()

This creates a FreeRTOS task and specifies which CPU core it is allowed to execute on.

C++ 
xTaskCreatePinnedToCore(
    Task1code,
    "Task1",
    10000,
    NULL,
    1,
    &Task1,
    0
);
⚠️ Tick ≠ processor cycle: FreeRTOS "ticks" are scheduler time units, not CPU clock cycles. The expression 1000 / portTICK_PERIOD_MS converts approximately one second into the number of RTOS ticks expected by vTaskDelay().
Parameter Meaning
Task function The function executed by the task.
Task name A human-readable task name.
Stack size Stack memory allocated for the task.
Parameters Optional data passed into the task.
Priority Relative scheduling priority.
Task handle Reference used to manage the task.
Core The CPU core on which the task is pinned.

10 // EXPERIMENT

Watchdog Timer Experiment

Let's test what actually causes watchdog trouble.

⚠️ Important correction: Do not deliberately replace vTaskDelay() with ordinary Arduino delay() expecting an automatic watchdog reset. In Arduino-ESP32, delay() generally yields through the RTOS.

Safe waiting

C++ 
vTaskDelay(
    200 / portTICK_PERIOD_MS
);

The current task becomes blocked for the requested time.

What causes trouble?

C++ 
for (;;) {
    // CPU-intensive work
    // with no yielding
}

A task that monopolizes a core and prevents required system work from running can contribute to watchdog timeouts.

A safer learning experiment

Instead of intentionally freezing the system, temporarily add a CPU-heavy loop inside one task and observe how system responsiveness changes. Keep the experiment short and be prepared for a watchdog reset.

C++ // EXPERIMENT 
for (;;) {

    volatile unsigned long long total = 0;

    for (unsigned long long i = 0;
         i < 500000000ULL;
         i++) {

        total += i;
    }

    vTaskDelay(1);
}
🚨 Do not treat watchdog resets as crashes to fear. A watchdog reset is a deliberate recovery mechanism. In real embedded development, you design tasks so they yield, block appropriately, or synchronize with the rest of the system rather than intentionally starving the scheduler.

12 // DEBUG

Troubleshooting

FreeRTOS errors can look intimidating. Start with the architecture instead of randomly changing code.

🔴 ESP32 keeps rebooting

Look for watchdog messages, stack problems, memory exhaustion, or a task that is consuming a core without yielding when it should.

🔴 Task never appears in Serial Monitor

Check whether xTaskCreatePinnedToCore() succeeded and verify that the task function actually reaches its first Serial statement.

🔴 Compilation error around task creation

Count the parameters carefully. Make sure the task handle uses &Task1 and the final parameter is a valid core number for your dual-core target.

🔴 Both LEDs are dead

Check GPIO numbers, LED polarity, common GND, resistor placement, and breadboard rows.

🔴 Core number isn't what you expected

Confirm the board is actually a dual-core ESP32 and that your selected Arduino-ESP32 version supports the pinning API being used.

🔴 Random instability

Look for tasks using too much stack, shared variables without synchronization, blocking operations, or excessive CPU consumption.

Advanced warning: Once two tasks access the same variable or hardware, "it works on my board" is not enough. You may need synchronization primitives such as mutexes, semaphores, queues, or task notifications to prevent race conditions.
13 // VOCABULARY

New Vocabulary

These are words you'll see everywhere once you start working with embedded RTOS systems.

Term Meaning
FreeRTOS A real-time operating-system kernel used within the ESP32 software stack to schedule and manage tasks.
Task An independently scheduled unit of work managed by FreeRTOS.
Core Pinning Restricting a task to a particular CPU core.
Scheduler The operating-system mechanism that decides which ready task should run.
vTaskDelay() Blocks the current task for a number of RTOS ticks, allowing other work to execute.
Watchdog Timer A recovery mechanism that can reset the system when required software responsiveness is not maintained.
Concurrent Multiple tasks making progress during overlapping periods of time.
Parallel Work physically executing at the same time on separate processing resources.
Race Condition A bug where the result depends on the timing or ordering of concurrent access to shared data.
