Core Concepts

01 // Multiple Inputs

The ESP32 is incredibly fast.

It can check the state of dozens of pins in the blink of an eye.

We will tell it to read pin 14 and then immediately read pin 15, over and over again.

02 // Absolute Logic

In Project 05, we had to build complex State Logic because the button toggled the LED.

Today we are using Absolute Logic.

We don't care what the LED was doing a millisecond ago.

The rules are absolute:

  • Did I hear a shout from the ON button? Yes? Turn the LED ON.
  • Did I hear a shout from the OFF button? Yes? Turn the LED OFF.

Because the ESP32 loops thousands of times a second, it will enforce these rules almost instantly.

Source Code

COMPLETE CODE

Delete the default code and paste this in. Look how much simpler the loop() is compared to Project 05!

C++ // main.cpp 
/*
 * ============================================================
 * MY BRO'S SIXTH ESP32 PROGRAM: START / STOP
 * ============================================================
 */

// Name our pins
const int LED_PIN = 2;
const int BUTTON_ON = 14;
const int BUTTON_OFF = 15;

void setup() {

    // Tell the ESP32 to push power OUT to the LED
    pinMode(LED_PIN, OUTPUT);

    // Turn on the internal pull-up resistor for BOTH buttons
    pinMode(BUTTON_ON, INPUT_PULLUP);
    pinMode(BUTTON_OFF, INPUT_PULLUP);
}

void loop() {

    // 1. READ BOTH BUTTONS
    // Store their current states in variables

    int stateOnButton =
        digitalRead(BUTTON_ON);

    int stateOffButton =
        digitalRead(BUTTON_OFF);


    // 2. CHECK THE "ON" BUTTON
    // With INPUT_PULLUP, a pressed button reads LOW

    if (stateOnButton == LOW) {

        digitalWrite(
            LED_PIN,
            HIGH
        );
    }


    // 3. CHECK THE "OFF" BUTTON

    if (stateOffButton == LOW) {

        digitalWrite(
            LED_PIN,
            LOW
        );
    }


    // The loop restarts instantly!
    // We don't need delay() because we aren't toggling.
}

06
Software Logic

UNDERSTAND THE CODE

Let's look at why this code is so clean.

🧠 No Memory Needed

We didn't create lastButtonState or ledState.

If the LED is already ON and you press the ON button again, the ESP32 simply commands it to go HIGH again.

Nothing breaks.

Independent if Statements

Notice that we used two separate if blocks instead of if / else.

This means the ESP32 evaluates the ON button and then separately evaluates the OFF button every single time it loops.

Why?

The Last Command Wins

The ESP32 reads code from top to bottom.

It reads the ON command, turns the LED on for a fraction of a microsecond, and then immediately reads the OFF command and turns it off.

Your eyes are far too slow to see that tiny transition.

Therefore, the command written last in the loop wins the tie.

11
Diagnostics

TROUBLESHOOTING

⚠
Both buttons do the exact same thing
Your wires might be crossed. Trace the wire from D14. It should only touch one button. Then trace the wire from D15. It should only touch the other.
⚠
One button doesn't work
Did you remember to write pinMode(..., INPUT_PULLUP); for both buttons in setup()? If you forgot one, that button's pin is floating and won't read correctly.
⚠
LED is doing the opposite of what I want
Check your if statements. With INPUT_PULLUP, a button being PRESSED means the reading is LOW.
