02 // CORE CONCEPT

What Are We Learning?

Today we're learning about State Machines and chained decisions using else if.

🧠 The State Machine

Imagine a vending machine.

When you walk up to it, it is in an Idle state.

When you put in a coin, it switches to a Ready state.

When you press a button, it switches to a Dispensing state.

It can only be in one of these states at a time.

🚦 Our Three States

We're going to create a memory box called trafficState. It will hold one number: 0, 1, or 2.

STATE 0
RED
trafficState == 0
→
STATE 1
GREEN
trafficState == 1
→
STATE 2
YELLOW
trafficState == 2

Every button press adds 1 to the state.

If the state becomes greater than 2, we reset it back to 0.

🔗 Chained Decisions — else if

In Project 06, we used independent if statements.

Today, we need the ESP32 to choose exactly one behavior.

IF state is 0 → do Red.

ELSE IF state is 1 → do Green.

ELSE IF state is 2 → do Yellow.

Because the decisions are chained together with else, the ESP32 will only execute one matching branch.

05 // CODE

Complete Code

This combines the Button Toggle logic from Project 05 with the Multiple LEDs from Project 03.

Delete the default code and paste this into src/main.cpp.

C++ // Arduino 
/*
 * ============================================================
 * MY BRO'S SEVENTH ESP32 PROGRAM: THE TRAFFIC LIGHT
 * ============================================================
 */

// Name our pins
const int PIN_GREEN = 2;
const int PIN_YELLOW = 4;
const int PIN_RED = 5;
const int BUTTON_PIN = 14;

// 1. STATE MACHINE VARIABLES
// This variable stores our current "State" (0 = Red, 1 = Green, 2 = Yellow)
int trafficState = 0;

// This remembers the button so we only count the "click", not holding it down
int lastButtonState = HIGH;

void setup() {
    // Configure our LEDs as outputs
    pinMode(PIN_GREEN, OUTPUT);
    pinMode(PIN_YELLOW, OUTPUT);
    pinMode(PIN_RED, OUTPUT);

    // Configure our button as an input with internal power
    pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop() {
    int currentButtonState = digitalRead(BUTTON_PIN);

    // --------------------------------------------------------
    // PART 1: LISTEN FOR THE BUTTON CLICK (STATE CHANGE)
    // --------------------------------------------------------
    if (lastButtonState == HIGH && currentButtonState == LOW) {

        // Move to the next state by adding 1
        trafficState = trafficState + 1;

        // If we go past 2, loop back to 0!
        if (trafficState > 2) {
            trafficState = 0;
        }

        delay(50); // Debounce to stop button glitching
    }

    // Save the button state for the next loop
    lastButtonState = currentButtonState;


    // --------------------------------------------------------
    // PART 2: EXECUTE THE STATE (CONTROL THE LIGHTS)
    // --------------------------------------------------------
    if (trafficState == 0) {
        // STATE 0: RED LIGHT
        digitalWrite(PIN_RED, HIGH);
        digitalWrite(PIN_YELLOW, LOW);
        digitalWrite(PIN_GREEN, LOW);
    }
    else if (trafficState == 1) {
        // STATE 1: GREEN LIGHT
        digitalWrite(PIN_RED, LOW);
        digitalWrite(PIN_YELLOW, LOW);
        digitalWrite(PIN_GREEN, HIGH);
    }
    else if (trafficState == 2) {
        // STATE 2: YELLOW LIGHT
        digitalWrite(PIN_RED, LOW);
        digitalWrite(PIN_YELLOW, HIGH);
        digitalWrite(PIN_GREEN, LOW);
    }
}

Save your code with Ctrl + S.

06 // CODE ANALYSIS

Understand the Code

This program has two major jobs: detect the button click and execute the current state.

PART 1 — The Trigger

State Update 
trafficState = trafficState + 1;

Every time you click the button, we take whatever number is currently inside the trafficState box, add 1, and put the result back into the box.

🔄 Wrapping Around

State Reset 
if (trafficState > 2) {
    trafficState = 0;
}

Our valid states are only 0, 1, and 2.

So if adding 1 creates state 3, we immediately reset it to 0.

0
→
1
→
2
→
0

PART 2 — Execute the State

This is where else if becomes powerful.

The ESP32 checks:

Is trafficState == 0 ? If yes → Red.

Otherwise, is trafficState == 1 ? If yes → Green.

Otherwise, is trafficState == 2 ? If yes → Yellow.

Because these branches are chained, only one state is executed at a time.

🧩 Why Every LED Gets a Command

Each state explicitly turns one LED HIGH and the other two LOW.

This is important because otherwise an LED could remain ON from the previous state.

Example 
digitalWrite(PIN_RED, HIGH);
digitalWrite(PIN_YELLOW, LOW);
digitalWrite(PIN_GREEN, LOW);

11 // DEBUGGING

Troubleshooting

If the state machine behaves strangely, check these first.

!
Button skips a light This usually means the button is bouncing or you held it slightly too long. Make sure delay(50); is inside the click-detection block and that lastButtonState = currentButtonState; is outside it, at the end of Part 1.
!
Two lights are ON at the same time Check every else if block. Each state should explicitly make one pin HIGH and the other two LOW.
!
A light doesn't work Make sure all three LED pins are configured as OUTPUT inside setup() .
12 // VOCABULARY

New Vocabulary

These two terms are extremely important as your programs become more complex.

Word Meaning
State Machine A system that can only be in one specific state at a time and transitions between states based on rules.
else if A way to chain conditions together. If the first condition is false, the next condition is tested.
