01 / Mission Brief

Hey my brooo 👋

Welcome back! We're about to remove one of the biggest beginner problems in embedded programming: making the ESP32 wait.

⏳ The problem with delay()

Up until now, we have used delay() whenever we wanted the ESP32 to wait.

But delay() has a massive problem: while your program is waiting, the code after it cannot execute.

Think of it like freezing the brain.

If the ESP32 reaches delay(3000), the current program flow waits for roughly three seconds. During that time, code that would normally read your button or sensor does not get a chance to run.

03 / Core Concept

What Are We Learning?

Today the main character is millis().

Blocking

A blocking operation prevents the current program flow from continuing until the operation finishes.

delay() is the classic Arduino example.

Non-Blocking

Non-blocking timing lets the program continue running while repeatedly checking whether enough time has passed.

That's what we're doing with millis().

1000
MILLISECONDS
Think of millis() as a hidden stopwatch.

From the moment the ESP32 starts running your program, the stopwatch keeps counting milliseconds.

Instead of saying "stop everything and wait one second," we say:

"Keep running. But every time through the loop, check whether one second has passed."

currentMillis − previousMillis ≥ interval
HAS ENOUGH TIME PASSED?
Important:

This is not true parallel execution on one CPU core. The ESP32 rapidly performs small pieces of work in sequence. Because the loop keeps running instead of sleeping, it behaves like cooperative multitasking.

06 / Source Code

Complete Code

Delete the default code and paste this into src/main.cpp. Look closely at the timing variables.

C++ / ARDUINO 
/*
 * ============================================================
 * MY BRO'S EIGHTH ESP32 PROGRAM: NON-BLOCKING MULTITASKING
 * ============================================================
 */

const int BLINK_LED = 2;
const int BUTTON_LED = 4;
const int BUTTON_PIN = 14;

// 1. TIMING VARIABLES
// unsigned long is the standard type used for millis() timestamps.
unsigned long previousMillis = 0;

// How long we want to wait: 1 second
const unsigned long interval = 1000;

int blinkState = LOW;

void setup() {
    pinMode(BLINK_LED, OUTPUT);
    pinMode(BUTTON_LED, OUTPUT);
    pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop() {
    // ========================================================
    // TASK 1: THE AUTO-BLINKER
    // ========================================================

    // Check the stopwatch right now
    unsigned long currentMillis = millis();

    // Has enough time passed?
    if (currentMillis - previousMillis >= interval) {

        // Save the current time as the new "last blink" time
        previousMillis = currentMillis;

        // Toggle the LED state
        if (blinkState == LOW) {
            blinkState = HIGH;
        } else {
            blinkState = LOW;
        }

        // Actually turn the LED on or off
        digitalWrite(BLINK_LED, blinkState);
    }

    // ========================================================
    // TASK 2: THE INSTANT BUTTON
    // ========================================================

    int buttonState = digitalRead(BUTTON_PIN);

    // Because there is no delay(), this check runs continuously.
    if (buttonState == LOW) {
        digitalWrite(BUTTON_LED, HIGH);
    } else {
        digitalWrite(BUTTON_LED, LOW);
    }
}

07 / Deep Dive

Understand the Code

This is where millis() stops looking like magic.

unsigned long

millis() returns an unsigned millisecond count, so unsigned long is the standard type used for storing these timestamps on Arduino-style ESP32 code.

On ESP32, int is normally 32-bit too, so the beginner explanation that an int can only reach about 32,000 is not correct for this board.

A 32-bit unsigned millisecond counter wraps after roughly 49.7 days. The subtraction technique we use here is designed to work correctly across that wrap.

currentMillis - previousMillis >= interval

Imagine you want to eat a snack every four hours.

01

Eat at 12:00

Write 12:00 on a sticky note. That's previousMillis.

02

Check the clock at 1:00

Only one hour has passed. One hour is not enough.

03

Check again later

Eventually the difference reaches four hours.

04

Four hours passed!

The condition becomes true, so you eat the snack and update your sticky note.

currentMillis − previousMillis ≥ interval
CURRENT TIME − LAST EVENT TIME ≥ WAIT TIME

🕐 currentMillis

The current reading from the ESP32's running millisecond counter.

📝 previousMillis

The timestamp recorded when the LED last changed.

⏱ interval

How long we want to wait before changing the LED again.

🔄 Update

Once the condition is true, we save the current time as the new reference point.

🧠 The proof

The ESP32 is checking the timer and checking the button repeatedly in the same loop.

That is the fundamental idea behind this style of non-blocking embedded programming.

delay(1000)

WAIT

The program waits for the delay to finish before continuing through the current loop.

millis()

CHECK

The program keeps looping and checks whether the required time has passed.

12 / Debugging

Troubleshooting 🐛

If the experiment doesn't behave correctly, check these first.

The LED never blinks

Did you forget previousMillis = currentMillis; inside the timing condition?

Without updating the timestamp, the condition remains true after the interval has been reached, causing the LED state to toggle repeatedly at loop speed.

The code won't compile

Check your variable declarations carefully. For millis() timestamps, use unsigned long.

Button LED does nothing

Check that the button is actually connected between D14 and GND and that the code uses INPUT_PULLUP.

LED is always off

Check the LED orientation. The long leg is normally the anode and should connect toward the GPIO through the current-limiting resistor.

LED is always on

Check your ground connection and confirm the code actually reaches both HIGH and LOW states.

13 / Vocabulary

New Vocabulary 🧠

These words are going to appear everywhere once you start writing serious embedded programs.

Blocking
Code that prevents the current program flow from continuing until the operation finishes.
Non-blocking
A programming approach where the program continues executing while checking whether an event is ready.
millis()
An Arduino timing function that returns the number of milliseconds elapsed since the program started.
unsigned long
An unsigned integer type commonly used to store millisecond timestamps returned by millis().
Timestamp
A stored value representing when an event occurred.
Cooperative Multitasking
Rapidly handling multiple activities by giving each one small pieces of processor time without blocking.
